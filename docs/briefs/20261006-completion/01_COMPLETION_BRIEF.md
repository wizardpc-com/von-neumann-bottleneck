## 3. 本轮要实现的三种闭环

### 3.1 玩法闭环：玩家不需要开发者陪同才能继续

内部评审版应有一条明确推荐路线，能够经历：
构造机器与核心瓶颈旅程 → 核心收束 → 表示 → 持续状态与服务 → 扩展收束。

这是体验组织，不是把现有并行章强改为线性前置，不是要求全部40个正式任务都必经。Prediction、服务追加委托与极限优化保持可选。

复用现有候选Hub和journey，补真实缺口：
- 普通启动能看懂从哪里开始、已走到哪里、什么是推荐主旅程和可选探索。
- 核心与后半程之间有可理解的衔接，退出、继续、返回、失败后重试不会把人扔回开发场景。
- 内部评审版可统一入口与视觉层级，但不强求统一存档文件或重写所有模型。
- 旧40关成果、有效解和已有核心结尾受保护；新内容不能使过去完成失效。
- 候选身份在构建说明中诚实标注，不靠删掉“候选”二字宣布正式发布，也避免每屏堆满QA说明挤占玩家内容。
- 没有完整试玩时间时优先检查真实衔接与风险点，不能用伪造进度表示从零全程通过。

### 3.2 教学闭环：操作明确，发现归玩家

共同体验应是：
**知道任务与工具 → 做出自己的方案 → 看见真实结果 → 解释变化 → 保存并继续。**

优先处理已暴露或本次实际观察到的断点，尤其：
- 序章不能默认玩家已懂端口、控制关系和存储时序；不借此重做完整数字电路课。
- 表示的准备任务优先让人分清“先付的准备成本、随后服务成本、实际占用”；跨资产任务明确同一方案服务不同资产。
- Service主视图先回答“我的方案是什么、谁在等、状态在哪里、哪项约束未满足”。精确向量、JSON、误差坐标、详细账单可追溯，但不同时压到主视图。
- 区分未运行草稿、历史实测、已获得成果，不因改动控件就更改旧指标或显示新成功。
- 必要时做少量短桥接或观察片段；不硬定新增关数，不引入全新模拟器，不要求每关必须先失败或重复跑两次。
- 允许保留和再次利用提前找到的好解。不会为了提高难度而让一个正确方案无理由失效。

可直接修措辞、反馈位置、信息分层、局部引导和可逆流程；大幅删关、改必经关系、破坏合法解或改变重要模型规则应留给团队裁决，不在无人值守时夹带实施。

### 3.3 主题闭环：先让玩家看见成果，再给文字

稳定主旨：**A Thought Within the World**。
作品中心仍是数据组织与有限资源下的系统构造，不是AI能力展示。

可用的情绪推进：
“我造出来了” → “原来它必须等待” → “我的安排改变了结果” →
“信息可以换一种承载方式” → “计算留下的历史也要有地方保存”。

这是帮助编排体验的解释，不改宪法既有两段旅程，也不新增三幕菜单或另一个结构系统。

今晚应做出可运行的收束初版，而不仅交一个未来结尾策划：
- 复用已获得的方案、真实运行或记录，展示玩家确实完成了什么。
- 分域展示不同模型，不伪装成这些方案已被接成一台真正的通用AI。
- 开场、关键衔接、核心结尾和扩展结尾有一致表达；不在每关重复主题口号。
- 存在有温度、可跳过、可回看的短文本即可。保留神秘感，但任务规格不能留白。
- 可以用现有画面与克制节奏建立一个低资产成本的结尾；完整美术、配器和精修叙述留给团队与Claude后续处理。
- 不能把资源瓶颈说成意识的科学证明，不能把一切限制都命名为冯诺依曼瓶颈；具体瓶颈可以被改善、消除或转移，主题不是宿命论。

启发创作的音乐与AI作品只作情绪参考。未确认授权的现成歌曲、旋律、素材不得直接打包进参赛构建。尤其不要把此前提到的 `world.execute(me);` 当成已获许可的背景音乐。

## 4. 内容收口与可扩展性的边界

**现在完成：** 已有玩法的进入、操作、理解、继续、保存和收束；必要的短过渡；可读性与跨语言一致性；可运行内部构建。

**留给后续：** 全作视觉定稿、完整音乐、故事最终版本、真人难度校准、其他机器安装与正式发行。
这些未完成项不阻止有边界的实现，但不能标成已验收。

**本轮不新增：** GPU/多核/Transformer/训练章节、通用预测器DSL、更多codec家族、联网AI、云同步、排行榜、研究模式、VPS部署或大规模新世界观。

“保持可扩展”具体意味着：
- 尽量通过已有任务/规则数据接入相近的新任务，稳定身份和版本关系可追踪。
- 叙事文本、主题样式、图像与音频尽可能沿现有资源机制替换，不与判定逻辑纠缠。
- 仿真提供事实，呈现层消费事实；音频、动效、字幕和播放速度不能改变结果。
- 保留计划、Trace、保存/版本校验与视图之间的清楚边界；新域不必强行共用万能执行器。
- 对当前确有风险的接缝做一个最小验证，例如替换一条文案/资源或用未注册小fixture接入同类型订单。可以复用已有证据；不为“未来可能用到”建插件平台或重构引擎。
- 输出具体能扩什么、局限在哪里、什么变化需要迁移。不能承诺“所有未来扩展都保证没有问题”。

## 5. 并行责任与执行权限

你是唯一主调度与整合者，使用实际可用的6.1 Sol High；子线程选实际可用的Sol High/Medium。配置能力先核对，不能以文字角色名冒充真实模型切换。不具备子代理能力时按相同工作包顺序推进，不假装已委派。

建议同时最多3个工作子线程；职责可按实际代码边界调整：

| 责任 | 主要工作 | 边界 |
|---|---|---|
| A：关卡与教学体验 | 表示/服务及已有主线的真实理解障碍、操作、信息层级 | 不独自修改共享导航、保存协议、成本模型 |
| B：主题与收束呈现 | 开场/过渡/结尾的可运行初版及局部呈现资源 | 不批量重写全作风格，不定稿小说 |
| C：独立验证与扩展边界 | 针对改动检查保存/证据、替代解、Mac候选身份和实际路径；复核A/B | 不把作者知解回放写成新手验证，不擅自修他人正在写的文件 |
| 主线程 | 统一路线、共享接口、集成、验收、构建、交接 | 对整体范围与事实声明负责 |

先划文件所有权，必要时使用独立worktree。共享Hub/导航/保存/构建配置由主线程或唯一指定负责人修改。每个线程独立QA profile；GUI与原生桌面输入只允许一个持有者。高资源Godot导入/导出与最终集成串行；不要把整夜耗在互抢焦点和重复启动窗口上。

本任务拟授予的本地执行范围：在已有项目权限内修改、测试、必要的本地分支/worktree、整合本轮成果、由主线程本地提交、生成独立候选包。不要把既有用户/队友未提交改动纳入提交。新分支或worktree建立前核对继承点，不机械开空白工程。
不授予push、合并main、改远端、强推、付费、提权、关闭系统安全保护、操作真实玩家存档、公网发布或生产部署。既有已确认的QA流程正常关闭自建窗口可以进行；不关闭无关窗口或进程。

普通可逆实现不等待主创逐项批准；重大规则、权限或资料阻断只暂停该项，其他独立工作继续。一个工具反复失败时记录明确缺口并改做可执行任务，不能绕过权限来凑验收。

## 6. 验证与长任务停止条件

先识别本轮会影响的风险，再选择必要检查。现有84套之类历史数量不是本轮必须重造的目标。
- 缺陷需用失败路径/反例定位；测试不可仅重复调用被测函数当独立oracle。
- 改动保存/共享导航时覆盖受影响的跨域进入、退出、重开、支持方案、命名方案与未运行草稿。
- 改动文案/布局时至少检查相关中英文最小窗口和关键控件可达，不把程序边界断言冒充目测。
- 保留替代合法解和性能/质量反例。不要为让测试绿而放宽合同或删除仍然正确的布局断言。
- 迭代只跑必要的目标测试；最终按跨域变更及仓库既有门槛做一次相应集成回归。全量只在这些风险或仓库门槛要求时跑，不让每个子线程逐次全量。
- 原生操作与最终导出包分开核对，源码版本、包身份、实际跑过的路径能对应。没有工具就标NOT_RUN，不回写假记录。
- 无音频设备/试听能力不能验收“不刺耳”；自动回放不证明新手能学会。
- 复用未受改动影响的旧证据，并写明旧证据的版本；不要把早期全程试玩与最后新包拼成不存在的一次验收。

沿用现有执行计划保存目标、版本、已完成、关键决定、所有权、证据位置、剩余动作与阻断。上下文压缩或交接前更新，换线程先恢复这个状态，不重新考古并重做。记录事实与简短依据，不记录隐藏推理。

不要只完成策划就结束，也不要为了“跑满一夜”找额外功能。
本轮完成、继续需要重大产品决定、不可安全前进或执行资源到限时，留下可运行的最好检查点和明确未完成项。禁止用“最终闭环”标签掩盖断点。
