# 团队讨论与 GPT／Claude 交叉审阅约定

> 这是今晚完成后的交接协议，不是要求今晚把审美、试听与真人学习效果也宣布完成。
> 本文中的角色分工是建议；主创尚未给出队友名单、技能与正式分工。

## 一、明天讨论的是可运行版本，不是又一份无限规划

主线程留下一个构建、一张旅程图、一个瓶颈改善片段与一个结尾初版。团队优先判断：
- 推荐主旅程能否成立，哪些任务应保持可选；哪里确实缺过渡，哪里只是看起来还想加东西。
- 主旨是否通过玩家自己的行动被体验到，而非最后突然喊一句口号。
- 要采用怎样的统一气质、叙述距离和声音方向。
- 哪些阻断影响比赛前交付，哪些愿望可以放到后续。

不要把所有队友变成此前参与设计、已经知道答案的试玩者。若有成员未看过方案，先安排其在不读攻略与测试解的条件下体验一个代表段落，再参与剧透讨论。人数少时记录角色与知情程度，不虚称独立样本。

## 二、GPT与Claude不是互相无限重写

推荐一次有边界的往返：
**冻结候选 → Claude审阅并做代表段落/分支修改 → GPT核验规则与教学 → 按证据修正 → 团队定稿方向。**

GPT侧重点：模型和证据一致、规则可解释、旧成果保护、交互可操作、性能/质量取舍。
Claude侧重点：信息层级、语气、视觉与叙述统一、过渡和结尾节奏、读者负担。
以上只是职责，不代表哪一模型天然正确；Claude也可指出技术漏洞，GPT也可提出审美异议。

每条异议应包含“具体画面/文案/操作 → 用户影响 → 证据或理由 → 最小改法”。区分：
- 可复现缺陷：实现者修复，另一方复核。
- 教学与交互假设：带代表版本交给人试，不争到某个AI投降。
- 审美偏好：由主创和队友选择，不伪装成客观bug。

不同AI使用不同分支/补丁，同一时刻只有一个整合者。不要在同一工作区争抢保存/导航/主题文件。
Claude先精修一段完整体验，团队认可后再推广，避免一次性全作换肤改文案后无法定位退化。
不允许为文案效果改变实际合同，不允许为正确性把界面退化成满屏调试信息。

## 三、今晚给Claude留什么

主线程只需给出实际位置与用途，不另建大型风格系统：
- 入口、任务说明、错误反馈、章节过渡和结尾的现有文案文件/入口。
- 当前主题样式、控件、图标、字体/图片/音频资源及来源说明的位置。
- 必须保持准确的术语、指标范围和状态区别，如草稿/历史实测、存储/流量、准备/服务、当前/已保存。
- 一段典型体验的截图或可重现操作，标记哪些是展示假设、哪些是实际结果。
- 不能改的模型、合同、保存边界；一份待讨论的风格问题清单，不规定全作最终配色。

目前不必把散落文案全部搬家，只有改动妨碍局部替换时才做小范围解耦。
`world.execute(me);`是创作启发，不是有授权的音乐素材。演出感、节奏与计算意象可以研究，未经授权的录音/旋律不能直接加入构建。

## 四、同学实际测试要回答什么

保持测试版一致并标记SHA/包版本、设备、语言、既有知识和是否看过答案。
先让测试者自己做，卡住时记下原因再给提示，不靠现场讲解掩盖教学断点。

| 观察面 | 核心问题 | 留下的证据 |
|---|---|---|
| 操作 | 能否发现入口、编辑、运行、找失败原因并继续？ | 卡住位置、原话、操作序列 |
| 教学 | 能否解释“这次为什么更快/更慢”，并在一个变化条件下作出合理判断？ | 口头解释和下一次尝试；不等同于统计学习效果 |
| 艺术与主旨 | 关键转折与结尾让人记住了什么，是否显得说教或突然？ | 自由回答，不先念主旨诱导 |
| 声音 | 耳机/扬声器听是否刺耳、过响、疲劳、突兀，静音后是否仍能理解？ | 具体时点、设备、音量与感受 |
| 连续性 | 退出重开后能否继续，方案和历史是否还在，支线是否误导？ | 保存/重启路径及前后状态 |

无需所有人各玩10小时。用不同人覆盖开场、关键瓶颈、表示准备/跨资产、服务响应/质量和结尾，另安排完整路径覆盖。实际时长从测试获得；不能把零散段落或AI知解通关相加，声称普通玩家主线用时。

测试资料默认本地与最小化；录屏/反馈采集先征得参与者同意。团队根据各自实际工作记录贡献与素材来源，不追溯编造署名、AI流程或研究结论。

## 五、形成下一轮有限修改单

按“阻断运行/丢成果 → 阻断理解 → 明显交互与听感问题 → 风格提升”处理。
一条问题一个可观察的改进目标；每次修正后复查该段以及受影响的相邻路径。
不要因为有人想要另一种游戏就改掉产品身份，也不要以宪法为借口拒绝真实的失败证据。

参赛赛道、提交截止、素材与AI披露要求由团队核对最新官方材料，未核实前不作为代码与对外承诺的硬条件。
