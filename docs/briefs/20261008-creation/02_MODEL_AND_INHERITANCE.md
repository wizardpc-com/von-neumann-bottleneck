# 三章共用系统：模型、成本与继承合同

本文是新增的技术深化建议，不是当前仓库已经实现的API。名字用于表达责任，Codex应优先适配已有类型，不照着文档机械新建全部类。理论来源编号对应 `01_DESIGN.md` 文末。

## 1. 首先冻结三个不同的问题

| 模式 | 可使用的材料 | 模型看到什么 | 输出被怎样解释 |
|---|---|---|---|
| 压缩／复原 | 编码端有完整原文；接收端有合法包和公开解码程序 | 编码模型允许来自公开示例，或来自计费的本次拟合；解码只用已恢复历史 | 与原文逐项相等才叫无损 |
| 预测／检验 | 已选训练材料、冻结模型、已经揭晓的上下文 | 不可看到未揭晓输入或未来统计 | 先提交预测，再得到真值和修正／误差 |
| 生成／创作 | 玩家模型、起始上下文、生成规则和独立随机状态 | 自己此前的输出，不存在后续标准原文 | 合法可展示的作品，不计算对隐藏原稿的正确率 |

最危险的错误不是数学太难，而是三个模式在代码或文案里互相冒充。

压缩允许编码端观察整段目标，但如果模型由这整段构成，就必须携带模型并计入成本；不能在预测章把同一目标改名为“未见数据”。

## 2. “同一台机器”应有两个清楚的层级

### 2.1 新三章之内：同一执行合同

共用一份机器配置、一种符号数据语言、一套规则盒状态格式和一个有边界的执行器。三种模式只更换作业与反馈关系，不更换隐含硬件常数。

机器配置至少能表达：计算吞吐、传输带宽／固定请求成本、有限存储、自动管理的缓存或模型行驻留，以及必要的工作空间。界面只开放本阶段有决策价值的项，不要把所有字段都变成旋钮。

模型计算必须产生真实事件：读取了哪些材料、访问了哪行规则、做了哪些更新、发出了什么符号。不是先调用不可见生成器，再反向绘制一段看似合理的CPU动画。

最初可以采用顺序执行器。编码、传输、解码分别执行，CPU和通道在不同时段空闲是实际调度结果。不必立刻支持异步并行，也不能画出模型没模拟的重叠。

### 2.2 与旧章节之间：有来源的封装／升级

当前表示、地址预测、服务使用不同教学模型。不要把相似字段直接强制拼在一起，或声称原来的低位宽电路逐条执行了所有新算法。

开工先列可映射的旧玩家成果：哪些配置、封装或布局可按既有语义继承；哪些只能作为来源、不能保留原周期；哪些新资源确实需要公开升级。

允许从旧方案建立一个有明确来源的新版本，但必须：

- 保留旧成果，不覆盖或改写旧成绩。
- 显示升级关系和仍生效的选择，而非只显示“继承成功”。
- 新三章内保持这一执行合同稳定。
- 新旧不同模型的周期不得直接排名。
- 暂不能执行旧电路时，如实称“在该构造基础上的新层级”，不能声称真实继承其执行。

这不是允许三套换皮实验。**至少新三章中的配置、模型与作品必须真实连续。** 若一开始只实现概念来源、尚无行为继承，应标为未完成关键目标。

## 3. 需要的最小数据关系

以下六类责任可以合并到已有对象，不要求六套新框架。

### MachinePlan

稳定身份、修订号、父版本、受支持的配置及来源。UI位置可以保存，但普通线长不偷偷进入模拟成本。相同配置及输入得到相同模型结果。

### ModelArtifact

模型类型／版本、符号表、有限上下文规则、真实计数、默认回退、训练材料身份、训练配置和机器方案关联。内容摘要由规范序列化产生，不能只用文件名区分。

### RunRecipe

运行模式、任务／数据版本、输入身份、模型快照或可靠不可变引用、机器配置、阶段设置。生成模式另含初始上下文、采样算法、种子与所需长度。

### RunEvidence

实际输出、真实事件、阶段成本、来源快照、揭晓范围和判定条件。编辑后不修改旧证据；不同模型版本的结果可并排，但明确不是单变量对照。

### PlayerWork

已确认的输出符号快照、名称、生成配方、模型版本、符号到图案映射版本、父作品／分叉信息。作品快照不依赖未来还能运行同版本算法。

### Session

当前草稿、当前章与观察位置、模型草稿／实测版本、命名方案、受保护完成依据及作品集合。复用已有租约、显式保存、恢复和脏状态保护，不把作品藏在会滚动清理的运行历史里。

关键关系：

```text
玩家机器 v1 ──修改──> 机器 v2
     │                  │
     └─示例学习─> 模型 m1 ──修改示例─> 模型 m2
                     │                    │
                压缩／预测证据         生成配方
                                          │
                                      作品 w1
                                          └─分叉─> 新配方／作品 w2
```

跨章应可直接使用原版本，再由玩家主动分叉。切章不能秘密训练或更换模型。

## 4. 推荐小模型：有限上下文的转移计数

这落实原稿的候选模型，避免引入完整训练框架。有限上下文计数和按后继频率采样有清楚、可检查的实现路径。[S2]

### 4.1 首版约定

使用小型固定符号表，首个切片可从4种符号开始。历史长度先考虑0／1／2：0作为忽略上下文的基线，1／2承担主要玩家选择。具体是否开放0给玩家由教学决定。

训练对每个选中示例独立遍历，累计：

`N[context, next_symbol] += example_weight`

示例权重首版可固定为1；只有确有创作价值时再增加可编辑权重。不同示例之间不能无提示地首尾相接，也不能默认做循环训练。循环与否必须是数据属性。

一个可显示的分布是：

`p(next_symbol | context) = N[context, next_symbol] / sum(N[context, *])`

没有完整上下文时，使用公开的更短后缀规则或全局计数；完全无经验时使用明确的默认分布。回退要产生可见事件，不用“神秘智能”填空。

### 4.2 首版不需要许多可调项

主操作优先是：选择示例、决定记忆长度、训练／重新学习。平滑、衰减、剪枝、窗口长度、状态预算、温度不要同时开放。

模型内存先采用硬上限：不能容纳时显示实际需求，不悄悄删除规则。若后续加入行淘汰或在线更新，必须公开确定性策略并计入写回／重建代价。

### 4.3 训练必须看得见

至少允许选中一个上下文，观察一次样例更新前后的后继计数，以及因此改变的候选分布。播放器可合并大量重复更新，但抽样展开必须来自真实事件。

“学习”不能只是Run按钮动画；样例改变应改变实际表内容。冻结模型的内容哈希不得因UI颜色、窗口尺寸、动画速度或读取手册而改变。

计数建议使用有界整数，指定溢出行为与规范顺序。若采用浮点权重，应同时说明跨平台重生成的限度；不能只凭同一种子承诺所有引擎版本输出完全一致。

### 4.4 手写规则和学习模型的关系

可以保留手填规则作为早期理解／调试模式；若玩家改写了规则，记录为手动修订，不把它冒称训练所得。

早期片段字典或RLE可继续作为独立codec，但进入预测之前必须有明确桥：玩家选择将哪些经验统计到规则盒，或将公开的确定规则表示成可预测规则。不要假定任意压缩文件都能自动给出后继概率。

## 5. 推荐桥：预测式无损包

这一节给出能让同一模型真正跨章使用的最低实现，不要求一开始开发算术编码或完整MDL优化器。

### 5.1 编码流程

设符号表大小为K，固定宽度原文每个符号用 `b = ceil(log2 K)` 位表示。首版可以选K为2的幂，使格式更简单。

发送一个包含以下必要信息的包：

```text
包头：格式版本、符号表身份、原文长度、模型/负载长度等
模型：规范化的可预测规则或计数表
起始上下文：解码所需的前k个真实符号
预测残差流：逐位置的匹配标志与必要修正符号
末尾：声明的位数、字节填充和必要的完整性信息
```

在每个后续位置，编码器只用模型和此前真实符号得到确定性预测。命中写一个匹配标志；未命中写另一个标志及真实符号。平局用稳定符号序裁决，编码和解码必须相同。

接收逻辑只拿到这个包与公开解码程序，不拿原文引用、全局资产数组或只在测试里存在的答案表。模型若已驻留两端，可通过显式身份引用省去重传，但第一次装载及替换必须付费，失配时不能暗中使用旧版。

### 5.2 解码与正确性

接收端从起始上下文开始作同样预测：匹配则使用预测，失配则读取真实修正。随后把**恢复后的符号**放入上下文，不能把错误预测写入历史。

逐步正确性的理由很简单：起始历史相同；若此前恢复相同，则本步预测相同；标志／修正使本步恢复原符号；因此下一步历史继续相同。实际实现仍须测试损坏包、截断、越界、缺失模型、零长度和未知版本。

压缩后字节变多不是损坏。RAW、RLE或预测式包可按公开合同比较，不要求玩家总选新codec。

### 5.3 比较必须包含模型，不夸大收益

只看简化的预测负载，设原文长N、模型上下文长度k、实际携带的起始长度 `s = min(k, N)`，后续失配数量为E，则：

`payload_bits = s*b + (N-s) + E*b`

总包还要加实际包头、模型序列化、身份引用、填充与校验等成本。这是特定教学格式的账本，不是最优熵编码长度。

尤其不能把四种符号的RAW按ASCII每符号8位，而预测包按每符号2位，用表示基线不公平地制造压缩收益。两边要使用同一公开符号编码假设。若本来就是完整字节资产，两边也都按字节语义处理。

规则表太大、样本太短或失配太多时，这个格式完全可能比RAW更大。应该展示这种事实，而不是调常数让所有作者推荐方案都获胜。

### 5.4 MDL式观察与实际传输分开

可显示“模型字节＋修正负载字节”来体现模型复杂度与解释能力的取舍。它只是有限格式下的两段描述，不是Kolmogorov复杂度，也不是对所有模型求得了最短描述。[S1]

若额外显示 `-Σ log2 p(x_t | context)`，必须标为理论编码／对数损失观察，不能将它直接当成已经实现并传输的包字节。只有真正实现相应编码器并统计边界、结束和模型成本，才可计入实际搬运。

## 6. 资源成本：哪些必须付，哪些可以明确简化

### 6.1 同一账本由事件生成

核心度量至少保留三类：真实传输字节、实际算法步骤的教学计算成本、任务输出结果。模型大小、残差、峰值与准备阶段在需要时展开。

实际实现一次操作，就记录对应事件与成本；再由这些事件汇总指标。不要UI算一套、判定又算一套，或先写目标分数再画符合分数的Trace。

### 6.2 需要交代的成本项目

| 项目 | 应计入什么 | 常见造假方式 |
|---|---|---|
| 学习／拟合 | 读取选定示例、计数更新、模型写入 | 自动训练，却声称没有准备成本 |
| 模型装载 | 模型真实序列化、传输、读取与必要展开 | 两端天然共享无限免费知识 |
| 编码 | 查规则、比较、写标志和修正 | 压缩体积变小，CPU工作却固定零 |
| 传输 | 包头、规则、残差、填充与实际请求 | 只计主payload，不计目录和模型 |
| 解码／预测 | 模型行访问、回退、符号恢复或选择 | 接收端查原文；预测器查隐藏后缀 |
| 生成 | 后继选择、随机采样、上下文移动、输出写入 | 播放预设序列或用免费联网模型 |
| 状态 | 有限模型表、上下文、输入／输出及临时缓冲 | 只计模型存储，不计解码后的工作内存 |
| 持久化模型／作品 | 任务中声明的机器存储代价；应用保存另有生命周期 | 将宿主系统的文件IO耗时冒充教学机器周期 |

应用层Save不应因电脑文件系统快慢改变解题成绩。游戏世界里“保存生成作品”的模型写出成本若属于合同，要由仿真显式表示，而不是测操作系统写盘时间。

### 6.3 一个公开的顺序模型就足够起步

可采用：

`T = T_prepare + T_encode + T_transfer + T_decode_or_predict + T_output`

每阶段按真实工作量、该机器的公开吞吐和请求成本计算。RAW也支付相同语义的读取、搬运与输出，不能故意漏计或加罚。

这只在顺序模型下直接相加；将来加入重叠，墙钟时间来自调度事件，不把CPU忙碌与总线忙碌重复相加。

原稿的“CPU忙／链路足”若当前模型没有后台作业，首版应写成“计算吞吐低／链路宽”，而不是画出不存在的CPU队列。若真加入后台占用，就必须有实际占用时间和调度，不能只改叙述。

### 6.4 跨次复用、RAW回退与热点

冷启动和复用运行分开报告，不能偷用上次缓存又宣称同条件。模型身份或内容变更后，旧驻留不能继续免装载。

RAW回退若是运行前的玩家选择，不需支付未执行的压缩成本；若先实际尝试压缩才决定回退，尝试成本不能被抹掉。

不同任务的机器和数据可公开变化以形成反例。一次对照要说明是只改模型、只改机器，还是多项同时变化；不把后者叙述成单一原因。

### 6.5 硬件怎样继续重要

在新三章里，有限记忆影响能保留的上下文／模型规模，数据量影响装载与搬运，计算吞吐影响查表更新和生成时间。不能后半程只剩样例按钮，CPU与通道成为永不变化的背景图。

但也不必每关同时优化三种资源。至少一个新的具体取舍应由已有机器安排改变，且影响可以在运行中看到。

## 7. 预测：让“未见”真的成立

### 7.1 状态与参数分开

首版默认：训练完成后冻结计数表M。测试过程中，用已经揭晓的真实符号移动上下文h，**不更新M**。更新h不是偷偷训练；它是根据真实历史做顺序预测的必要部分。

以后需要在线学习时另行公开规则：必须先预测并计入误差，再根据本次真值更新，不能先更新再评分。不要在首版同时混合冻结、在线、回灌训练三个概念。

### 7.2 一次正确的事件顺序

```text
读取已可用上下文
→ 用冻结模型提出预测/分布
→ 记录并锁定该次预测
→ 揭晓本步外部真实符号
→ 计算修正信息/误差
→ 将真实符号放入下一步上下文
```

求预测的函数只接收M与已揭晓前缀等白名单输入，不接收完整流、测试集ID到答案的查表对象或未来统计。

可以预计算确定性Trace以方便回放，但屏幕、公共代理接口、累计指标和模型调用都必须遵守揭晓边界。在某个前缀处换掉未来后缀，此前预测必须保持完全相同。

### 7.3 数据分工

- **示例集**：玩家能选择和查看，用来学习。
- **调试／验证片段**：玩家反复试、看反馈，用于选择方案；不能称为一直未见的最终测试。
- **冻结检查**：冻结模型后使用未参与调参的片段。揭晓后记为已见；再次重放还是同一项可复现检查，不重新标成新泛化证据。

切分以完整序列／来源为单位，不能把同一序列的重叠窗口分到两侧再声称独立。数据预处理、符号表扩充、示例筛选统计也不能看检查答案。[S4]

不需要给单机游戏建设保密测试服务器或反作弊平台。保护的是模型信息边界和教育解释，不是假装本地素材绝对不可查看。

### 7.4 好的反例要靠实测，不靠导演

要观察“训练更好、同族新片段更差”，就用真实模型和固定可复现材料测出来。不要写成 `if model_size > threshold: add_error()`。

两份数据来自不同规律时，是环境变化；模型在稀疏上下文里没见过足够例子，可能是覆盖不足；不能统统叫过拟合。[S5]

有限阶模型可能无法体现原稿设想的全部现象。此时先调整教学问题或示例族，或增加有明确必要的小能力，不直接扩大到复杂神经网络。

### 7.5 难度、重试与完成

冻结检查可包含数条同族片段，目标公开、难度可达到。重试不收费、不清掉旧设计；已看答案的事实可以如实记录。

基本完成允许可靠但不极限的模型。多次尝试不是科学独立实验，完成记录也不等于普遍泛化证明。

## 8. 生成：同一模型，另一种闭环

### 8.1 最小算法

```text
M = 玩家选择的已学习模型快照
h = 玩家起始片段
repeat 到公开长度或停止条件:
    q = M 对 h 的后继分布
    y = 使用指定采样规则和独立PRNG从q选取符号
    输出 y
    h = 将 y 推入有限上下文
```

第一轮默认**只更新上下文h，不用自己的生成结果继续训练M**。否则容易把自我强化误称为“学到了新事实”。以后可以研究自适应创作，但不属于此次最低闭环。

后继分布来自玩家模型，采样只选择其中的可能性。回退到更短上下文／默认分布时明确记录。不存在的规则不能由幕后答案补齐。

### 8.2 变化程度不必第一版就做完整温度系统

最小生成器只需按计数比例采样，另可提供确定性最大后继作为对照。若提供分布集中度，定义并记录转换规则，说明它改变随机性而非智能或创造力。[S3]

例如可在正权重上使用公开的整数变换，降低对跨平台浮点的依赖；若用温度，则指定归一化、零概率和采样细节。不要为按钮名称发明科学量。

变得更随机不保证新颖、有结构或好看。局部合法后继也不保证长程结构。模型能力边界应写进设计，不在结果很乱时默认增加更多随机性。

### 8.3 可控对照

允许固定起始片段与随机种子，改变一个示例选择或记忆长度，再比较作品；同时展示模型／配方差异。

固定种子也不必保证两种不同采样实现逐步使用相同随机调用数量。若实现不同，明确对照边界；最好首版固定每步的采样协议，避免把渲染或音频的随机调用混入生成器。

切换语言、暂停、窗口焦点、音量与播放速度不能改变输出序列。每个已发出的符号都对应M、上下文、分布、选择和输出事件。

### 8.4 没有隐藏真值，不等于没有合同

可以检查：符号合法、公开长度满足、资源允许、模型／来源完整、结果能够完整展示和保存。不能根据与秘密图案距离、熵或重复率决定作品是否够美。

本学习路线使用的模型应确由玩家选定样例产生，不能生成时换成默认训练结果；纯随机或手写规则可作为明确标记的对照，而不是伪装成已经学习。

玩家确认作品后才形成“我选择留下它”的结果。不强迫用指定名称、不要求随机刷到某个审美阈值。

## 9. 保存：作品快照与配方同时存在

### 9.1 作品快照

保存实际输出符号、顺序、显示映射版本和玩家名称。它是未来可以原样回看的已确认作品，不因再训练或模型升级被自动替换。

需要图片预览时从快照派生；预览不是唯一作品数据。首版不必同时开发视频、MIDI、音频和分享码导出。

### 9.2 生成配方

至少保留：机器方案、模型状态／规范字节、示例内容或不可变可访问副本、训练配置、起始上下文、生成规则、采样器与PRNG版本、随机种子／初态、输出长度、相关模型和格式版本。

“只存几个可变文件路径和一个种子”不等于可复现配方。摘要只能识别内容，不能在内容消失时替代内容。

### 9.3 重新播放与重新生成是两个按钮含义

**播放作品**直接使用已保存快照，未来模型升级也应保留其原样。

**按配方重新生成**在兼容实现下核对输出。若版本不再兼容，保留原作品，明确说明；不得静默生成另一件后覆盖。

**继续修改**从配方创建新的可撤销草稿／分叉。旧作品与受保护完成依据独立保留。

### 9.4 不重复建设文件基础设施

复用已有会话保护与恢复机制的合适部分，为新作品定义严格、有限、可迁移的载荷。未知版本、超限内容、损坏包和未来字段保留／拒绝的行为必须明确。

新域先使用隔离候选profile，不对真实旧档做试验。不要把所有旧方案强制迁到新大schema，只为保证三章“看起来统一”。

## 10. 与现有仓库的最小接缝

以下路径是复用定位，不是未经阅读即可改写的指令。

| 定位 | 复用方向 | 不直接照搬的部分 |
|---|---|---|
| `experiments/representation_region/` | 字节／分块读法、成本呈现、历史与准备反例 | 当前64B资产、RAW/RLE特定预算不能直接变成新符号模型通则 |
| `experiments/prediction/predictor.gd`及相邻实验 | 前缀因果、先预测后揭晓、回看标记 | 地址步幅不是内容学习算法 |
| `experiments/service_plan/` | 状态访问、写回、质量和反例的可见表达 | 固定递推不是示例学习；四流服务不是新三章必经课 |
| `experiments/candidate_session/` | 来源快照、命名、保存／恢复与成果保护 | 不把滚动历史当作品库；不猜已有schema已支持所有新字段 |
| `src/campaign/`、统一旅程入口 | 正常进入、准确返回、推荐顺序和成果展示 | 不改变旧任务有效解，不把推荐虚线改成新硬锁 |
| 已有 `SimulationTrace / SimulationEvent` | 同源事件与只读呈现 | 新语义不冒充旧receipt；扩展字段和版本应有明确合同 |

建议只在一个有界新域里建立连续信号工作台。可以新增模型文件，但不建设容纳未来所有AI的总引擎。三个章节共享新域内部的明确合同；旧域按必要接口衔接。

## 11. 高价值验证矩阵

不要求堆断言数量。优先跑能抓住这条设计根本错误的检查，并遵守仓库既有必需门槛。

| 风险 | 必要检查 | 不足以替代它的证据 |
|---|---|---|
| 假无损 | 隔离编码／解码，接收端只拿合法包，字节往返与坏包拒绝 | 同一个数组在两边显示相同 |
| 假压缩 | 规范序列化实际计长；RAW基线公平；模型和头部纳入 | 仅显示 `-log p` 或预设压缩率 |
| 假成本 | 阶段事件可重算总量；短样本／低带宽等条件真实反转 | 为特定codec写奖励或罚分 |
| 偷看未来 | 固定前缀、替换后缀，此前预测完全相同；模型调用白名单 | 只是界面隐藏未来轨道 |
| 训练泄漏 | 按序列划分；模型冻结；已揭晓检查标记；训练来源审计 | 把相同答案换个测试集名字 |
| 假学习 | 修改一个样例产生可解释的计数／分布变化 | 播放训练进度条 |
| 假生成 | 生成路径无未来原稿；使用自己模型及输出回灌 | 预制动画或来自另一个模型的漂亮结果 |
| 假继承 | C→P→G携带同一版本，修改后有父子关系且行为可解释 | 相同皮肤、名字或无效机器编号 |
| 作品丢失 | 保存、重开、分叉；旧快照不变；版本不兼容不覆盖 | 只检查同进程重放 |
| 艺术误判 | 不同意图的配方能有可辨别结果；由人观察并选择 | 熵更高、种子不同或断言全绿 |

压缩成本反转、不同上下文的预测差异、两份作品的可辨别变化，都需拿实际运行例子记录。本文没有为它们提供虚构的通关性能数值。

## 12. 本合同尚未证明什么

尚未证明有限上下文模型足以支持团队希望的最终审美，尚未校准新关卡预算，尚未验证输入长度与训练负担，尚未选择最终光纹映射与声音。

这些不是停止实现的理由，也不能通过交一份报告假装解决。先把同一系统的连续切片做出来，用实际输出决定是否扩充章节或局部模型能力。
