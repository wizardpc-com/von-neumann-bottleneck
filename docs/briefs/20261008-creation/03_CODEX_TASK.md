# Codex 执行任务

## 1. 当轮目标

以主创和Ray原稿为基准，继续扩展《冯·诺依曼瓶颈》，实现“压缩→内容预测→创造”的连续新内容。**不是继续只修按钮、写结尾文字，也不是重新规划整款游戏。**

目标成品是：玩家沿用同一套自己构造的系统，形成规则或从样例学习小模型，先无损复原信号，再在未见片段上预测，最后用同一模型生成并保存自己的作品。记忆、服务、回应进入用途和资源约束，不额外扩第四个新章。

先完成一条真正可玩的贯穿切片，再深化为约三章候选内容。不要只交三份设计文档、三个互不关联的实验台，或一个与前章无关的生成按钮。遇到会话、工具或权限边界时停在安全检查点并交接，不以部分原型冒称全部章节已完成。

## 2. 必要上下文

主创现在有队友，计划以教育游戏方向参加数媒比赛。此次开发目标是作品内在完整性与主题深化，而不是为了比赛增加知识点。比赛的当前资格、日期和材料规则不由这份任务书确定；不代报名或对外承诺。

之前一些指令强调“只收尾、不新增章”，那是旧阶段范围。本次主创已明确要求继续扩展压缩、预测和创造；可以为它们新增有边界的模型与玩法。禁止万能引擎、伪造因果和覆盖玩家成果等底线仍然有效。

艺术命题：真实世界不仅限制计算，也提供可以组织、学习和创造的结构。玩家最后应带着自己的作品离开，而不是只获得一张性能成绩单。

故事边界：壹在独立小说的结尾开发游戏；玩家不在关卡中制造历史上的壹，也不通过小模型证明意识或AGI。

## 4. 默认实施选择

这些是可逆起点，不是未获确认的最终美术设定：

- 单一离散光纹／灯光信号媒介，静音也完整成立。
- 一个连续信号工作台，保留CPU、内存、通道和缓存的可见关系。
- 有限上下文转移计数小模型，主要从选择的示例学习；手填规则可作早期桥接与调试。
- 新压缩章后半优先采用“同模型预测＋修正”的真实无损包，明确计算模型及元数据成本。
- 冻结模型先预测后揭晓，再以同一模型进行输出回灌生成；生成时不自动用自己的输出训练模型。
- 作品快照和完整配方分开保护；基本创造完成不靠隐藏美感分数。

发现默认方案无法支撑所需玩法时，先给出小型反例与可行替代，再在本范围内修正。不能为了遵照文档强塞一个没有辨别力的生成器，也不能直接换成联网大模型。

## 5. 按有价值的检查点推进

### M0：把真正的技术接缝讲清并跑通

只写一份短的执行合同：机器与模型如何继承、RAW基线怎样编码、包里包含什么、训练与预测分开在哪里、作品怎样重放。必要的合同确认不应变成重新审计全仓数日。

实现最小训练／规则盒、编解码往返、预测调用边界和生成回灌。至少有一次真实模型内容变化和一个来自模型的输出。界面尚简陋可以接受，伪造输出不可以。

**不能停在M0就交付“新三章完成”。**

### M1：完成贯穿切片

一条普通候选路径做到：

`继承机器 → 编码包送达并还原 → 带入规则盒预测未见片段 → 主动切换生成反馈 → 保存作品与配方 → 退出重开 → 原样回看／分叉`

其中至少有一个真实压缩反例、一项真实未见检验，以及一个由玩家选择导致的模型／输出差异。反例不要求玩家在每次正式通关前故意失败。

可以先隔离候选存档，但入口、返回和保存必须能操作，不只命令行脚本。作品应立即可见，不把所有艺术呈现留到以后。

### M2：把切片长成章节

按 `01_DESIGN.md` 的C/P/G内容单元深化：

- 压缩：可复用规律、修正、模型成本、机器／数据条件变化。
- 预测：前缀判断、必要记忆、背诵与泛化、冻结检验。
- 创造：生成回灌、意图驱动修改、作品选择与保存收束。

编号和独立关数不必逐字照搬。合并短关或复用旧 Representation 任务时保留学习递进；新章不能只剩同一编辑器更换标题和阈值。

可利用现有Service做状态用途或可选深化，不要求完成全部旧合同才能进入新内容。旧地址预测依然可选，新内容预测承担三章内的桥。

### M3：接成可讨论的作品

在已有旅程中设置清楚的候选入口与推荐路径，保留原40关及既有第二幕结尾。新的创造结尾展示实际作品和可追溯来路，不把旧完成作废。

整合关键操作、提示、来源、脏状态、暂停／回放及保存恢复。提供同一版本的可运行检查点，准备给团队和Claude的具体审阅片段。

完整艺术、试听、真人理解与跨设备验证可以尚未完成，但必须准确列出。它们不阻断有边界的候选开发，也不能被代码测试宣称完成。

## 6. 主线程与并行工作

由主线程统一负责产品范围、共享合同、集成与交接。沿用用户选择且客户端实际可用的Sol High／Medium等配置，不虚构创建了未提供的子代理。

适合最多三条并行实现线：

| 工作线 | 责任 | 必须协调的边界 |
|---|---|---|
| A 模型与成本 | 有限上下文学习、真实包、纯模型执行与成本 | 先与根线程确定快照、事件、包格式，不自行重写旧模拟器 |
| B 玩法与呈现 | 单工作台、C/P/G内容、三轨反馈、作品展示 | 使用实际模型；接口未完成可搭UI，但不得用占位成绩做验收 |
| C 独立验证与成果保护 | 因果边界、逆向解码、继承、作品／配方、兼容 | 与主线程共同处理共享保存，不能另外造一套进度权威 |

依赖未解决时先做独立工作，不通过三个分支各发明接口来假装并行。共享导航、保存和公共配置只由一个整合者修改；GUI只允许一个操作者；每条验证线独立profile，禁止共用可写试玩档。

子线程结果应有代码、必要验证和已知限制，不只写建议。主线程必须实际阅读与整合，不能直接拼接三个完成报告。

## 7. 权限与变更范围

本任务用于项目内的实现、隔离测试和本地候选。可以建立必要的隔离开发工作区，在已有规则允许或已明确授权时进行本地提交。没有明确Git写入授权时，不把“开发”自行扩大为commit／push／合并。

不授权：覆盖他人改动、破坏真实存档、重写历史、修改远端配置、付费或提权、公开部署、报名、上传玩家材料或导入未授权音乐。

本次允许在新域内实现小模型、编解码语义及候选载荷，须由主线程明确版本与成本合同后推进。涉及旧玩法规则、既有前置、正式存档迁移或大范围架构变化，先保护旧成果并说明影响；不能用“扩三章”作为无限改写许可。

一般可逆决定自主选择并继续。权限或材料阻断仅暂停受影响项，不假装绕过，也不把整轮退回等待主创。

## 8. 必要验证，不堆测试数量

执行 `02_MODEL_AND_INHERITANCE.md` 的高价值矩阵，重点是：真实包往返、公平字节账本、成本反例、模型确由示例改变、前缀独立、冻结检查、生成无隐藏真值、跨章继承以及作品保存重放。

相关代码迭代跑最必要检查，复用仍适用的旧证据；跨域整合和交付遵守仓库必需门槛。需要CI或全量验证时执行一次对应冻结源码的检查，不在每个小文案改动后重复所有测试。

针对当前具体失败排查，不预设都是过时测试；不得为绿色结果降低旧保护语义。新增目标先明确模型规则，再从真实多方案数据校准；不能硬编码作者偏好的赢家。

原生或viewport验证优先覆盖两个模式转换、一次失败定位、一次作品保存／重开。已知答案的代理证明可操作性，不证明新手能发现。截图、无声播放和音频实际试听分别记录。

## 9. 最终交付

至少包含：

1. 实际完成的连续C→P→G路径及其入口；三章当前范围、完成与未完成内容。
2. 一个可打开的候选构建或项目检查点，和明确源码身份；导出受阻时不虚构发行包。
3. 一份真正由模型生成、玩家流程选择并保存的示例作品及其配方；标明属于知解QA示例。
4. 关键真实反例：压缩更小不一定更快，训练／未见表现区别，生成与预录不同；不保证每个假设都会按预期成立。
5. 重要前后变化、必要验证结果、剩余风险。明确哪些只是设计推理、哪些已运行。
6. 团队／Claude交接：具体文案与显示映射接口、不可修改的语义边界、需要人检验的理解与审美问题。

保持一份权威执行计划，按语义阶段更新目标、当前SHA、决策、剩余项与下一步。不要每次小修都复制一套“最终报告”，也不要保留彼此矛盾的多个“当前包”。

完成当轮范围后收口，不为了持续运行扩新领域。若仅M1完成，如实交付M1和接续状态，不能宣布三章已成品；若M2/M3还能在本次执行安全完成，继续落实，不以第一份原型为默认终点。

## 10. 人的下一轮任务

团队不必读代码证明模型对不对，重点观察三个片段：知道一次压缩成本反转的原因，解释一次未见预测失误，说明自己怎样让作品发生变化。

Claude先精修同一小段图案／转场／作品呈现，不无边界改全作；GPT检查语义和数据来源；主创选择审美方向。同学未看答案先试，记录卡点与原话。不要先告知“你应该理解世界既限制又创造”，再用复述证明主题成功。

最终叙述、音频、真实时长与教育效果仍待验收。当前唯一需要先落地的承诺是：**不是让玩家相信自己创造了，而是让他实际拥有一次可理解、可重复、可留下的创造过程。**
