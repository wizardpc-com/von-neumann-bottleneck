# 冯·诺依曼瓶颈：游戏宪法

## 序言

> **让玩家亲手构造系统，在信息的存放、移动与使用中发现限制，再用自己的安排，让系统完成原本难以完成的事情。**
>
> **A Thought Within the World**
>
> 思考并不悬浮于世界之外。理解它的来路，不必消除对它的惊叹。

这是一份方向性文件，不是逐关策划、实现清单或比赛申报书。它规定作品应成为什么、什么值得继续投入、哪些边界不能被一次新灵感悄悄越过。关卡数、具体预算、界面布局、模型版本和开发排期，由下层设计文件决定。

正文是本次审计提出的产品裁决；附录保留事实依据、历史分歧及当前行动方向。它不把助手过去的赞同当成主创已经批准的决定，也不自动授权提交代码、发布作品、改变许可或报名参赛。

---

## 一页总纲

| 要确定的事 | 本宪法的裁决 |
|---|---|
| 产品身份 | 一款以数据移动与有限资源为核心的、有限可完成的系统构造解谜游戏 |
| 玩家最重要的获得 | 我造出了自己的方案；我看懂了发生什么；我的修改确实有用 |
| 差异化中心 | 不只让机器会算，而是让玩家组织数据的位置、到达时机、承载形式和持续状态 |
| 主题表达 | 通过可追溯的计算过程抵达 **A Thought Within the World**，不靠反复宣讲 |
| 现有作品 | 保留五区域的构造与优化主线、玩家成果和有效解；不为新主题推倒重做 |
| 后半程 | 优先完成“表示”，再以“持续状态与服务”形成有限综合收束；预测保留为有独立价值的可选探索 |
| 当前开发方向 | 从增加独立原型，转向把已成立的内容做成同一款完整游戏 |
| 完成尺度 | 玩家能独立开始、试错、理解、继续、保存并抵达结尾，而不是功能数或测试断言数 |
| 范围纪律 | 保护正确性和玩家成果；资源不足时缩减新范围，不用未完成功能拖住整部作品 |
| 创作关系 | AI扩大执行能力，主创保留产品判断、审美取舍与对作品的理解；不以消耗额度决定开发量 |

# 第一编：作品是什么

## 第一条　游戏首先对玩家的体验负责

《冯·诺依曼瓶颈》的首要身份是**系统构造解谜游戏**。教育价值、专业表达与艺术气质应当强化这款游戏，而不是成为玩家必须忍受枯燥的理由。

主要服务于喜欢工程、编程、自动化或逻辑解谜，愿意观察、试验和调整方案的人。进入时不要求预先学过缓存、体系结构或数值计算；但也不承诺所有玩家都会喜欢这类思考方式。新手得到足够清楚的工具与规则，有基础的玩家得到更自由的方案和更深的权衡。

产品承诺不是“学会整个计算机科学”，也不是“亲手造出通用人工智能”，而是：

> **设计自己的系统，看清信息在哪里受阻，再用自己的办法使它工作得更好。**

正确的知识是地基，可理解的操作是入口，创造与发现是乐趣，视听与叙事赋予这一过程感情。它们应共同成立。不能以好玩为理由伪造因果，也不能以严谨为理由把游戏做成难以使用的实验报告。[^1][^2]

## 第二条　数据组织是中心，造机是有价值的起点

保留从逻辑、存储到可运行机器的构造体验。它的价值在于让玩家拥有自己的机器、理解可组合的规则，为后面的系统问题建立共同语言。

但作品不与其他游戏比赛谁能覆盖更多门电路、指令集或现代处理器细节。其重心始终是：**计算为什么被信息供给拖住，以及怎样重新组织计算、存储与移动。**

因此，不能依据旧文件中的“去掉门电路”重做今天的主线；也不能因为已有造机内容，就让基础构造无限加长。应保留已经成立的创造体验，减少重复接线和无新发现的劳动，让数据移动的独特问题尽早被玩家感知。[^2][^3][^4]

“保护现有内容”保护的是玩家成果、有效解和作品连续性，不是给每一处历史设计永久豁免。未来有足够证据时，可以调整节奏、合并重复内容或设计有明确来源的进阶入口，但必须单独说明理由、学习承接和兼容方式。

## 第三条　主题是理解的终点，不是强加的答案

**A Thought Within the World** 是全作稳定的精神主旨。主标题继续使用《冯·诺依曼瓶颈》，英文主题作为副标题与叙事线索；改名不是当前发展的必要条件。

两者的联系在于：玩家处理的计算不是没有代价的符号变换。数据需要被表示、存放、传送、使用，历史需要被保留，预测可能失败。随着工作负载变得复杂，玩家仍能追溯其行为的来源。

这里必须保留三个界限：

- **技术概念不能无限泛化。** 不把所有资源限制都命名为“冯诺依曼瓶颈”，也不把它说成一切智能必然遭遇的同一种瓶颈。
- **限制并不等于宿命。** 具体瓶颈可以被消除、绕开或转移；好的设计确实改善结果。作品讲的是在条件之内创造，而不是“努力最后都没有用”。
- **艺术命题不是意识证明。** 游戏可以表达“复杂智能仍有物质条件”，但几个教学模型不能证明人类意识的完整本体，也不能把线性递推直接等同于思想。

主题应在整段旅程中累积，不要求每个教学节点都承担哲学证明。一个用于练习、缓冲难度或欣赏机器运行的片段，也可以有正当位置。

## 第四条　完整作品应有终点，也允许继续生长

作品采用两段能够独立收束的旅程，而不是不断延长的知识目录。

**第一幕：造出机器，认识限制。** 保留现有“构造 → 时间 → 局部性 → 时序协作与位置安排”的主线。第三、第四章的并行关系不因书写顺序而改变。玩家在这一幕末尾已经完成一段有意义的经历，不必等新章节齐备才得到结尾。[^2]

**第二幕：改变承载，维持连续过程。** 表示让玩家决定信息以什么形式存在；持续状态与服务让玩家安排历史、资源与回应。后半程的终局是完成一个有明确用途和公开约束的系统方案，而不是突然切换成完整机器学习课程。

**预测属于可选的深化路线。** 它承担“依据有限历史行动、为猜错付出代价”的问题。它可以与时序协作或后半程相连，但没有证据表明必须把它立为人人必经的大章。它与状态服务也不需要为凑一条概念链而共享一个万能仿真器。[^5][^6]

“40 → 45 → 49”保留为曾提出的分段交付思路，**不是宪法中的关卡配额**。正式任务数包含主线与可选内容，不能把总数说成全部必经；也不为凑49删掉好关或添加重复关。每次发布只承诺实际完成的范围，并保留此前可成立的结尾。[^1]

# 第二编：玩家怎样体验

## 第五条　玩家拥有方案，而不只是找到正确选项

核心循环是：

> **理解任务 → 构造方案 → 运行 → 观察证据 → 改变假设 → 再次验证 → 保存与继续。**

电路、程序、数据布局、表示分块、请求顺序和策略规则，都可以成为玩家的设计对象。作品应让玩家看见“这是我的方案”，而非在几个预设中找出作者藏好的答案。

但**构造感不等于所有地方都必须拖线**。边界适合直接编辑，顺序适合排列，简单参数适合选择，代码适合表达可组合的程序。若把同一个参数选择画成五个必须连接的模块，却没有新增决策，只是增加体力劳动。对照实验允许用少量选项隔离变量；综合任务应给予更充分的表达空间。

预设、模板和已有组件可以降低重复劳动，但必须清楚标明来源。它们不能暗中替换玩家实现、赠送“自己完成”的记录，或绕过应有的验收。已经挣得的抽象与封装应保留玩家创造的连续性。[^2]

判断交互好坏，看它是否让意图更容易表达、差异更容易理解，不看按钮、节点或代码行的数量。

## 第六条　教会操作与规则，把策略留给玩家

**可以直接教怎么操作，必须公开系统怎么工作，尽量让玩家自己发现怎么做得更好。**

端口语义、操作码、单位、数据范围、写入时机、可用工具和失败条件不是谜底，不能藏在高阶提示或世界观谜语里。猜不出哪个按钮能按，不等于正在进行有价值的探索。

“先体验后命名”是减轻术语负担的方法，不是禁止提前给规则；“自由探索”也不是拒绝必要演示。入门关可以提供一个可拆解的小例子、一次明确操作或可观察的中间状态，再逐步撤去支持。Factorio的开发复盘同时记录了过度指挥与引导不足的问题，本作不把其中任何一端当成教条。[^7]

提示应主动请求、逐层增加信息，可返回、可重看。完整参考需要明确的剧透提醒，并与玩家工作区隔离。使用提示不羞辱玩家，不损害其继续体验的资格；但提示使用也不能被冒称为独立发现。

新手体验应尽早出现一个有意义的闭环，随后尽早预示本作独特的数据问题。不要求玩家先记住整本手册，也不以固定分钟数替代真实观察。若设置快速体验入口，应是诚实标记、来源明确的独立体验，不伪造主线组件或完成状态。

## 第七条　关卡用决定推进，不用知识点和手续凑数

一个关卡首先要回答：**玩家这次在决定什么？做错或做得不够好时，会得到什么可继续使用的信息？**

构造、观察、受控比较、诊断、优化与综合可以采用不同节奏。短关不必同时具备全部功能；综合关也不应突然要求未介绍的新机制。连续任务可以使用相同操作，只要问题发生了有意义的变化。

内容进入正式旅程，至少要说明它带来的新决定、已有能力的迁移，或明确的节奏价值。规模增加、换数据和变预算都可以服务设计，但不能把这些变化本身当成足够的理由。

开放优化与综合关应接受有意义的替代方案；教学关不必硬凑“两种硬件解加两种软件解”。只要符合公开契约，非标准边界、不同连线和提前想到的好方案都应被承认。**玩家复用一个好设计，不是必须纠正的漏洞。**

不强迫每关先失败，也不普遍要求运行两个方案、点击若干证据、填写一次预测再准许继续。只有“做对照”本身就是本关主要任务时，才要求必要的实验过程；其他时候，充分的行为结果可以直接证明方案合格。不能把学习设计变成领取通关印章的手续。

## 第八条　性能是谜题的一部分，极限优化不是所有人的义务

清楚区分三个问题：输出是否符合要求、资源是否满足任务合同、方案是否还可改善。

本作不能把所有性能目标都降为无关奖励，否则“瓶颈”将失去玩法地位；也不能让每一关只接受近乎最优的解。基础通过给予可靠进展，进一步优化提供独立的挑战与个人记录。[^8]

多个指标应保留其含义。快、少搬、少存、少准备、及时回应和保持精度，不能随意压成一个不透明总分。总线更忙不必然更好，某一次命中率更高也不自动等于整张订单更快。

比较必须交代条件。不同任务、不同模型、不同精度合同的成绩不能直接混排；过去的运行记录不随当前控件改变。对近似计算，允许误差必须提前公开，并由实际数值产生；同时保留适当的精确路线，不让低精度成为剧情指定答案。

玩家应能保存、命名、复制、回看和继续改进自己的方案。欣赏一台运行得流畅而清楚的机器，也是奖励，不必全部转化成排行榜或社交系统。[^9]

## 第九条　世界可以留白，任务不能空心

创作内部保留基础设定中的联系：这套程序可以是“始祖”为后来的人留下的理解计算的路径。**这个作者侧设定，不等于开场必须披露的剧情。** 始祖身份细节、历史年代、文明全貌以及最终揭露方式继续保留空间。[^10]

玩家眼前仍应有具体目的：接通一段能回应的系统、恢复一份可读档案、使同一批内容按时抵达、让连续请求获得结果。任务不只是“将指标降至某数”，也不需要为此增加城市建设、战斗或角色养成。

世界线索主要通过系统留下的修订、档案、任务用途和少量可跳过的文本出现。规格与因果始终可信；叙述可以保留疑问，但不能用不可靠旁白偷偷改变玩法规则。

结尾应先让玩家看到自己的系统完成了什么，再把此前的构造、等待、位置、表示和历史放到一起。可以有凝练的文字与音乐收束，不必把所有模型接成一台虚假的通用机器，也不要求玩家作出“崇拜还是拒绝”的道德选择。

应保留好奇、惊喜、幽默和温度。留白不是删除叙事，去除神秘化也不是去除美。我们借鉴好作品组织好奇心的方法，不照搬它们的情节与谜底。[^11]

## 第十条　美术与音乐是体验本身，但不遮挡系统

整体气质采用**清楚、克制、略带年代痕迹的计算空间**。系统、数据与玩家方案居于视觉中心；世界感通过材质、空间、节奏和留白建立。具体色板、字体、图标与动效留给视觉设计，不在宪法中冻结。

共同的界面语言要稳定：哪里看任务，哪里编辑，哪里运行，哪里判断结果，哪里展开证据。各域可以拥有不同工作台，不必长得完全相同。错误应出现在容易看见的位置，说明不满足的条件，而不是只留下编号或红叉。复杂证据分层展开，不能靠塞满屏幕体现专业。[^12]

视听采用“双重观看”：第一次看，能感到机器在工作、等待、恢复；想继续追究时，能追到真实事件。视觉合并和音乐抽象可以存在，但不能捏造某条传输、性能改善或通关结果。

声音应优先支持专注，再在关键发现中展开。可以用稳定而低存在感的主题动机，把系统状态、节奏密度与声部变化联系起来；不逐个事件发尖锐提示，不把低效方案做成持续惩罚耳朵的噪声。低效仍应可以平静研究，高效也不意味着越来越吵。

Mini Metro的声音创作提供了数据与音乐相连的实例，但本作不照搬其音频与部分仿真时序互相影响的做法：**音乐、画面、播放速度绝不改变本作判定。** 静音、减少动态与降低特效以后，全部关键证据仍然可得。[^13]

美术和音乐不必等代码全部完成后才开始，也不应先量产几十份资产。先在真实工作台与一段完整体验上验证统一语言，再扩展到全作。

# 第三编：怎样把它做成

## 第十一条　真实因果与玩家成果是不可交换的底线

同一份合法方案和同一组输入，应由明确的模型得到可复现结果。仿真、指标和Trace同源；UI、声音、提示、回看和遥测不能成为第二套判定权威。[^2][^14]

采用有边界的教学模型，而不是伪装真实硬件的精密数字。普通导线的视觉长度不参与延迟；缓存由模型自动管理；显式暂存、准备、重编码、写回或预测浪费，按相应域公开的语义计费。未模拟的成本应说明，不借主题之名宣称覆盖能量、物理距离或真实AI性能。

不同章节可以采用不同抽象层级。统一术语与交互，不等于统一重写所有仿真器。跨域综合只在确有玩家价值、接口清楚且可验证时推进；禁止先造一个包容未来一切机制的总引擎，再等待关卡出现。

保存保护创作，版本保护解释。新内容不能默默覆盖旧设计、未知字段或未来格式；旧成绩的适用版本应可辨认，当前完成依据应有可重算的支持。规则变化必须保留设计并给出迁移或重新验证的理由。具体schema、文件名和数据结构属于工程方案，不是宪法条款。

任何审计结论都必须区分“已复现缺陷”“合理风险”和“尚未验证”。不能只凭一段摘要或读错代码就宣布测试造假；也不能因为测试全绿就宣布不存在缺陷。

## 第十二条　完成意味着可交付，不意味着一切可能性都已实现

所有内容明确区分三种状态：

**实验**证明一种机制或设计假设是否值得继续；**候选内容**让它具备连贯任务、可用界面和可测试入口；**正式内容**则兑现对玩家的完整承诺，包括恢复、导航、兼容、实际运行和足够的体验验证。

允许在隔离候选构建中接入导航与保存，以便测试真正的完整流程。不能设置“没有正式入口就不能验收，但未验收又不许建立候选入口”的循环门槛；也不能把候选登记自动当成已经发布。测试入口与正式产品承诺应清楚区分。[^15]

完成证据必须分层：模型正确、界面可操作、玩家能理解、最终包可运行，彼此不能代替。已知答案的输入回放不是新手验证，有限启发式失败也不是关卡质量证明。人工观察可以委托适合的试玩者与专业审阅者，不要求主创独自完成所有测试。[^5]

暂时缺少真人证据时，可以继续有边界的候选开发与技术验证，但必须保留风险，不能声称学习效果、可理解性或长期听感已经过关。继续扩内容也不能成为永远不检验旧体验的理由。

默认保持离线、单人、键鼠可玩的完整本体。账号、在线反馈服务器、云服务和实时模型调用都不是开始、保存与结束游戏的前提。当前免费开发与测试不自动承诺永久免费；未来定价、商店与许可另行决策，但不能靠分拆必要教程、提示或保存功能来解决产品问题。

比赛与科研是作品的出口，不是作品的主人。对外仅展示真实版本、真实贡献和实际支持范围；不为临时评分规则新增无关系统，不用演示视频掩盖不可运行的本体。素材、音乐、字体与AI参与需有来源和授权记录，玩家数据默认最小化并尊重同意。

## 第十三条　按完整体验推进，按主创注意力约束并行

当前以一名学生主创配合AI执行为现实组织方式。并行编码能够加快局部工作，但设计选择、整合、验证与维护仍需要有人承担。**开发规模应受可以消化的成果约束，而不是受可用模型额度驱动。**

每轮围绕一个可以验收的玩家问题组织工作，例如“玩家能否在表示关里保存两种方案并读懂取舍”，而不是同时堆“UI升级、故事升级、引擎升级、更多关卡”。目标应先限定值得投入的时间、审阅负担和范围，超出时优先削减外围承诺，而不是不断延期或削弱正确性。[^16]

默认集中完成一条正在进入游戏的内容链，并行安排边界清楚的模型验证、视听样例或独立研究。共享保存、导航、公共控制器与模型版本由单一整合者负责；不能让多个线程分别决定一套新规则，再交给主创收拾。

AI交付应围绕可运行样例、实际变化、关键证据与剩余决策。实现者和审阅者应尽可能使用不同的验证视角，不能以重复调用同一段被测逻辑代替独立检查。子线程、提交与断言数量不是效率指标。

主创不必手写每个函数，但必须逐渐拥有对核心玩法、模型边界和主要取舍的解释能力。游戏应继续提供创造的乐趣，而不是把主创固定成无限批阅生成物的审核员。

## 第十四条　宪法限制方向漂移，不阻止具体创造

在不破坏既定规则与玩家成果的前提下，关卡编排、措辞、具体美术、交互细节和可逆实现可以自主推进。宪法不要求每一个按钮等待主创批准。

改变产品身份、主线范围、核心学习路径、玩家已有权益、重大模型含义或世界观结论时，应明确提出修订，而不是夹带在普通开发任务中。一次必要的修订只需回答：**原来保护什么，新证据是什么，为什么更改，如何保护现有玩家，以及哪些旧文件因此失效。**

文档分三层维护：宪法保存方向，设计与路线图保存选择，状态与验证记录保存事实。历史文件标明日期和适用范围；不能让多个“最终版”同时发号施令。现有仓库的安全与权限规则继续有效，文档冲突应显式解决。[^14]

当两个好想法争夺资源时，先问：

> 它强化的是玩家的决定，还是作者的功能清单？
>
> 它让现有作品更完整，还是又制造一个必须补完的前提？
>
> 不增加它，当前这段游戏是否仍然能成立？

# 附录A：本次产品审计与方向裁决

本附录是2026年10月3日的判断，不随正文永久冻结。

## A1　证据范围与当前事实

本次核对了当前两份附件、检索到的相关历史设计与试玩材料，以及GitHub最新状态、核心原则和实验说明。早期长篇重构清单按产品、引导和交互主题检索；两份同内容的试玩纪要不作两个样本。外部参考采用开发者、创作者、官方产品说明与方法作者的一手资料，来源见附录C。

本次GitHub读取确认main为`05c3bf0988199e8396fb1094fd5ac4d64f3fa4f6`。正式游戏仍是五区域40任务；最新候选内容为表示5任务、预测3项调查、服务方案3项合同，均在实验区。Ray框架使用的`39d0441f / 52f1a79`是更早基线，不是当前全部实现。[^5][^17]

仓库记录对冻结实现`e4e359006d61619955551c2ca54e447077a07448`完成了54个常规套件及导入、隔离用户目录检查。**这是本次阅读核对的仓库证据，不是本次重新运行的测试。** 本轮没有亲自运行游戏、试听、检查原生发行包或开展新人试玩；因此以下是产品与设计审计，不是新的发布验收。[^5]

## A2　真正值得保护的资产

**核心机制已具备可发展的统一问题。** 构造、缓存、时序、布局、表示和状态不只是按课程拼接，它们能够围绕信息如何到达计算形成不同决定。最新表示已有真实准备成本和跨资产方案，服务方案已有可编辑请求组与实际状态编码。[^2][^6][^18]

**工程证据与玩家所有权已有基础。** 确定仿真、Trace、封装来源、可编辑方案、历史对比与存档保护，能够支持“我的修改为什么有效”，不应因美术更新重写掉。[^2][^14]

**主题与媒介具有内在联系。** 玩家的操作可以揭示复杂行为的来路，世界观不需要另造一套昂贵的玩法系统才能附着。这是设计判断，不等于已经验证了所有玩家的情感体验。[^10]

## A3　主要风险不是“还少哪门知识”

| 风险 | 已有依据 | 本次裁决 |
|---|---|---|
| 开场离独特乐趣较远 | 早期方向稿担心重复造机；历史试玩出现规格不清、构造难以下手 | 保留造机，但以尽早形成完整循环和预示数据问题为体验目标，不再加长基础清单 |
| 代码与证据增长快于整体游戏 | 最新新内容仍为多套隔离入口，正式化与原生、真人证据未闭合 | 下一阶段以连贯体验和接入质量为主，不继续横向创立新领域 |
| 自由探索被误解为缺少说明 | 试玩纪要具体记录了不知道操作码、部件功能和下一步 | 基础规格直接给，策略按需提示；不能把迷路归咎于玩家不够聪明 |
| 学习过程变成手续 | 既有及拟议设计含比较、诊断、证据定位等完成要求 | 这些只在有教学必要时成立，不提升为全游戏统一门禁 |
| 大量通过测试造成过度信心 | 仓库明确区分已知目标回放、有限策略与真人；某些日志仍有已知诊断问题 | 精确报告证明了什么；不以断言数判断乐趣，也不把代理停滞解释为“第五关很优秀” |
| 主创被无限生成物消耗 | 历史创作材料与本轮委托均体现AI执行多、个人审阅时间有限 | 减少同时待整合的方向，保留主创看得懂、愿意参与的样例与关键取舍 |

上述历史试玩说明曾经出现过哪些问题，**不据此断言当前版本仍有相同bug**。当前缺口是这些改善在陌生玩家身上是否充分成立，仍需新的证据。[^3][^4][^5]

## A4　与Ray框架及历次讨论的关系

Ray框架最值得吸收的是：有限完整产品、核心与扩展分别闭合、玩家成果保护、验证分层，以及故事留白。其逐关合同、排期与具体工程结构则属于可修订设计，不宜全部升格成宪法。[^1]

本次明确处理以下分歧：

**不把49任务写成最终命令。** 那是“表示5＋状态4”的一条方案；最新Service Plan只有3项候选合同，Prediction另有3项调查。要不要新增状态入门、保留几个预测节点，应由学习承接和体验决定，而非算术凑数。

**不倒退到旧模型补新界面。** 新表示区域已加入准备摊销与跨资产约束；新Service Plan已有实际字节编码、请求分组与不同资源账本。Ray框架引用的旧状态实验数值和固定batch1方案，不能直接覆盖现在的模型。[^6][^18]

**不再把Prediction视为只有概念。** 当前已经有有界历史、猜错污染与真实流量代价；但“有了机制”仍不等于“必须增加主线大章”。[^5][^19]

**不把过往助手意见当新缺陷。** LRU遗漏曾被误报，后续证据已澄清；本次不把它列为待修。相同纪律适用于未来任何“源码明显不可能通过”的判断。[^17]

**不把题型包装成定理。** “每关只有一个变量”“每关必须两类解”“每关先失败”“主题应在每关被证明”“所有参数必须改成拖线”都不作为硬规则。它们各自有适用情境，机械执行反而会制造重复、排斥有效解或增加交互劳动。

**不承诺不存在竞争者。** 早期文件的“市场空白”不足以支撑全球唯一的结论。定位应通过真实游戏片段证明，而不是依赖竞品永远不做类似机制的假设。[^4]

## A5　现在应推进的总体路线

### 第一阶段：把现有核心与一段新内容接成真正的玩家旅程

继续修复已有核心的阻断与信息问题，同时选择表示区域中的一个代表片段，把任务、构造、运行、比较、保存、退出恢复与视听语言接完整。以最新候选为起点，不再从头写一套R1–R5来替换它。

该阶段需要一个可以直接交给别人玩的版本，以及明确的开场和现有核心结尾。无需先做完全部配乐、全部新关或跨域引擎，才能让人体验。

### 第二阶段：使表示成为完整内容更新

保留已经成立的分块、内容差异、热点、准备成本与跨资产问题；依据实际学习曲线决定是否补一个短入门、如何排序及哪里需要难度缓冲。优先修正“为什么这份订单失败、下一步可以比较什么”的可读性，不用削低全部目标换通关率。

在隔离候选中完成新域保存、导航、版本与旧玩家兼容，再按证据纳入正式范围。核心结尾仍保留，表示末尾也应有阶段性满足，不把状态章的完成作为表示内容成立的前提。

### 第三阶段：以持续状态与服务完成后半程，而不是继续扩课程

使用已成熟的可编辑Service Plan作为基础，分层让玩家理解“留下什么、先服务谁、用什么形式保存、怎样达到公开质量与资源要求”。必要时补足状态入门，但不预先规定必须四关。

预测同步维持有边界的可选路线，先解决它自己的理解与表达，不强行嵌入服务引擎。最后用真实完成的服务与玩家代表方案收束主题，避免又为“更像AI”新增一整套训练、Transformer或意识系统。

**近期不优先开展的工作：** 新的大知识领域、更多并列旧实验入口、为了统一而重写全部模拟器、复杂角色和过场、常驻云端AI、无必要的账号或社交平台，以及尚无实际玩家问题支撑的抽象框架。

这不是停止扩展，而是把扩展从“多开一个实验”改成“多完成一段游戏”。
