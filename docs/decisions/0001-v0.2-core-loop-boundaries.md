# ADR 0001: v0.2 core-loop boundaries

- Status: Accepted
- Date: 2026-08-15
- Superseded in part: the mutually exclusive drawer decision is replaced by ADR 0002 after direct interaction feedback.

## Context

Prototype v0.1 proved deterministic cache-locality simulation but left several interactions weakly coupled: the language described only a narrow pattern, wiring asked the player to reconstruct a prescribed topology, animation did not strictly follow visible connections, Profiler occupied permanent space, and Cache capacity did not yet form a clear goal-level tradeoff.

## Decision

- A Python-shaped DSL is parsed into nested, source-line-aware IR. `SimulationCore` executes this IR recursively and has no separate traversal switch.
- The current level owns one fixed topology. It is connected and laid out automatically; devices may be moved for readability but players do not edit connections.
- `SimulationEvent` is the causal presentation contract. Source highlight, route animation, component state, and Profiler evidence must derive from its source line, route devices, and details.
- Program, Test Bench, Profiler, and Cache were initially implemented as mutually exclusive drawers. ADR 0002 replaces only this presentation choice; Profiler still presents player-generated facts and does not recommend code changes.
- Test Bench evaluates the Official goal as correctness plus at most 105 cycles. Cache hardware cost is displayed and recorded but is not a hard pass/fail condition.
- Cache capacities remain 1, 2, or 4 lines with costs 4, 7, and 13 so a low-cost software solution and a higher-cost hardware solution can meet the same target.

## Alternatives considered

- Preserve the v0.1 syntax: rejected because compatibility would keep two concepts of execution alive; the v0.1 tag already preserves that interface.
- Keep manual wiring: rejected for this level because the required graph has one correct arrangement and creates setup repetition rather than a meaningful decision.
- Compute presentation routes from device centers or duplicated coordinates: rejected because moved components would make packets disagree with visible wires.
- Keep Profiler permanently visible or give optimization advice: rejected because it reduces the machine view and converts investigation into instruction following.
- Cap hardware cost as part of the Official pass condition: rejected for v0.2 because recording the tradeoff allows both solutions to remain valid and comparable.

## Consequences

- Simulation, playback, feedback, and investigation can be checked against one deterministic trace.
- The level focuses player agency on code and Cache budget rather than fixed wiring.
- Old DSL text is intentionally invalid on v0.2.
- GraphEdit is used as a movable visual topology, not as a general circuit authoring system.
- The 105-cycle target validates multiple solutions but does not claim that their costs are balanced for a future progression system.
