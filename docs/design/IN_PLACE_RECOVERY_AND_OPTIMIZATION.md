## 1. 这次真正吸取的教训

### 1.1 保留 simulation 不等于保留游戏

原游戏的资产不仅是模拟器，还包括玩家已经会用且在意的选择、移动、擦除、分支、撤销、方案保存、任务窗、提示画布与封装复用。只保留计算内核、替换整个交互路径，依然是实质重做。

### 1.2 简洁不等于减少自由

应该减少的是默认遮挡、无关常驻窗口、重复解释和无意义操作，不是删除玩家修改方案的能力。任务清楚与画面简洁需要同时成立，不能把任务缩成不显眼的一行，再把答案作为常驻辅助。

### 1.3 规格、提示与答案是不同的信息

Opcode、端口作用、位宽、测试目标是题目规则，不能藏在 Hint 后。该检查哪种关系属于线索；完整电路属于答案。任务默认清楚，提示默认隐藏，两者并不矛盾。

### 1.4 通过测试的入口必须就是玩家实际打开的入口

模拟器与旧编辑器测试都绿，不能证明新主线使用了这些能力。场景中加载参考拓扑、调用内部方法或打开 Test 模式能通关，也不能证明用户鼠标能够选中、删线和分支。

本轮验收优先检查能力是否在普通 Game 的实际路径中可达，而不是继续堆功能清单。

## 2. 修正后的产品路线：在原游戏上改，不另起一套

### 2.1 本轮保留的路径

```text
原序章 / Hardware Foundations
基础连线
  ├─ Half Adder → Full Adder → ALU
  └─ SR Latch → Register → RAM
               ↓
          CPU 关内集成
               ↓
          LOAD / STORE
               ↓
Chapter 1：计算、等待、RAM 与总线
               ↓
Chapter 2：缓存、局部性、工作集与分块
```

本轮暂时保留既有节点及前置关系，恢复为普通 Game 的默认路径。不是宣布 9＋5＋7 永远最优，而是先恢复可比较的旧版，再基于实际体验判断局部内容要不要合并。没有新证据前，不再强制压缩到八关，也不把原游戏藏入“高级模式”。

### 2.2 仍需改善，但用局部办法解决

| 原设计问题 | 这次允许的增量修改 | 不再采用的替代方式 |
|---|---|---|
| CPU 一次性信息过多 | 用已有关内阶段、清楚 opcode 表、局部目标与端口说明降低信息负荷 | 把 CPU 变成预接完整的演示，只留少量按钮 |
| ALU 容易机械布线 | 明确运算、选择和 Carry 的要求，调整布局、失败反馈及 Hint 线索 | 默认删除构建关或替玩家接线 |
| SR→D 认知跳跃 | 行为规格说清，S/R 推导方向置于 Hint；必要时给另一个不泄露本题答案的小例子 | 把公式和整题电路默认放在主画布 |
| RAM 位宽、寻址不清 | 端口说明、地址/值显示、足够布线空间、数据与控制的视觉区分 | 锁住全部接线以避免玩家犯错 |
| 任务重复啰嗦 | 已教操作不再反复出现，规格集中且可回看 | 过度压缩到看不见任务要求 |
| Chapter 1/2 流程冗长 | 后续分别核查预测、回放、比较与总结，按具体卡点减少冗余 | 在本轮恢复期一并换掉整个判定/流程系统 |

继续围绕数据流和瓶颈组织后续体验，但不以这个主题为理由牺牲用户认可的构建玩法。

## 3. 旧能力保护契约

以下主要适用于原本支持自由构建的电路关。Chapter 1 的固定系统槽位、外部测试端子和只读观察关按其既有明确规则处理，不借恢复之名新增一个通用硬件编辑器。

| 能力 | 必须保持的实际表现 |
|---|---|
| 选择与移动 | 主体可选、可拖；端口拖线优先级清楚；文本框失焦后能够恢复画布操作 |
| 放置与方案 | 旧元件台、拖放/重复放置、命名方案继续可用；不能只在旧场景中存着 |
| 删除与擦除 | 玩家可删除合法编辑对象和连线；右键命中跟随视觉接触，不隔空删除；可撤销 |
| 线网分支 | 从线段中间、显式接点、线端与已有网络续接到兼容输入；交叉不自动连接 |
| 撤销与复制 | 编辑事务恢复模型和视图；保留旧快捷键，不把“简单化”做成只允许重置整关 |
| 连接自由 | 基于位宽、方向、电气约束接受或拒绝；错误解法允许构建，再由行为测试反馈 |
| 观察自由 | Hint 与回放可限制改图，但可移动镜头、缩放、查看元件；退出不能残留只读状态 |
| 表达清晰 | 电平0/1、方向、位宽、线路与选中状态各自可区分；沿用已接受风格再局部优化 |
| 结果可信 | 可见图决定输出；没有隐藏答案、自动修线或按作者参考边列表伪造成功 |
| 旧成果 | 工作台拓扑、位置、线色、命名方案、自建元件与进度安全保护 |

特别注意：旧 ADR 0015 明确 Hint 返回通过快照重建方案，撤销历史重新为空。[R3] 本轮不得把“保留撤销历史”假装成旧能力。先恢复旧规则并明确记录；改为保留内存历史属于额外改进，不能为此展开另一轮架构重写。

## 4. Mission：显眼的题目，不是常驻答案

保留旧版 Mission 的可移动、可收起、可关闭/重开和 Previous/Next 机制。

首次进入关卡，必须在显眼且不被其他窗盖住的位置显示：任务名称、应达到的行为、输入/输出或状态要求、必要限制、测试目标。开始操作后缩成醒目的短目标，详细规格仍可随时展开。玩家主动关闭后，保留明确的“任务”入口。

不是把所有规则强塞进一个短段落。复杂规格使用表格、元件详情、可定位的端口解释，并保持原说明可回看。CPU 的 opcode 表在该关需要时可钉住。

默认整理靠初始位置、窗口尺寸和打开数量；不要整体重写成固定布局，也不要把必要说明移到不显眼的角落。可选吸附或布局预设若不破坏自由，可留作后续改进，本轮不另做停靠系统。

### 示例：Register 任务正文

> **留住输入**
> 做一个能保存一位数据的寄存器。
> `LOAD=1` 时写入 D；`LOAD=0` 时保留原值。
> 写入后改变 D，保存值不能跟着变化。

这属于规格。`S = D AND LOAD` 和 `R = NOT D AND LOAD` 是具体解题关系，不能同时作为常驻任务文本显示；应按需要在提示中逐级揭示。模型在测试边界提交状态的规则必须在首处明确，不让玩家误认为实际电平锁存时序。

## 5. Hint：独立画布、分层请求、明确防剧透

### 5.1 本轮建议状态流程

```text
正常编辑：题目/规格可查，解题提示隐藏
  ↓ 用户点击 Hint
H1 独立只读画布：思考方向＋必要接口
  ↓ 主动请求更多，并确认将揭示局部解法
H2 独立只读画布：关键关系＋有意选取的局部子电路
  ↓ 主动请求完整答案，出现明确的确认
H3 独立只读画布：完整参考
```

这些确认门槛是对用户本轮要求的实施建议，不是对旧版已具有全部确认机制的事实描述。旧版已具有独立画布与三个内容层级。[R3]

### 5.2 门槛的目的与边界

门槛用于避免误触、让玩家主动决定何时接受更多帮助。默认采用单独请求、层级确认和剧透警告，不采用倒计时、必须失败若干次、扣分、联网或羞辱文本。

H2 提供“返回方案再试试”和“查看更多提示”两个明显选项；H3 的确认文案明确“将显示完整参考答案”。快捷键和双击不能意外连续越过多个层级，键盘操作也能完成确认。已看内容再次查看不重复惩罚，但不自动解锁更深层。

### 5.3 独立画布必须真正独立

- 标明“提示画布 · 只读”，与当前玩家方案明显区分。
- 可平移、缩放、检查元件，不允许在这里正式测试、封装或更改玩家方案。
- 不在主画布上覆盖答案线，不做半透明自动答案预览，不自动补线。
- 不提供“把参考整体导入当前方案/一键完成”。玩家在自己的方案里复制粘贴仍然保留。
- 保存所见层级与当前查看页，重开不偷偷显示新层级。
- 返回时活动方案名、拓扑、位置、线色不变；相机/选中状态按旧规则尽量恢复，历史行为如实说明。
- Hint 不产生通关凭证，不改变待测行为；完整参考也只能作为参考。

主线性能关将来需要图/程序提示时也应遵守同一主动揭示原则，但本轮不因此创建第二套跨章节提示引擎。

## 6. 架构修正：回接原路径，谨慎提取新改进

### 6.1 可以复用的旧基础

`src/hardware_foundations/circuit_graph_edit.gd` 的分支、擦除和输入体系；旧 Hardware Foundations 场景与控制器；Mission、Components、Inspector、独立 Hint、工作台存储、玩家元件库；现有 simulation、Trace、内容注册、Game/Test 隔离、存档和 telemetry。[R2–R4]

这不是要求把每个文件硬恢复成某一历史提交。应先看本地 diff，确认旧实现是否仍在、哪些部分被新入口绕过，再选择性恢复接入与相关逻辑。

### 6.2 新版修改如何处置

按三类处理：

| 分类 | 处理 |
|---|---|
| 直接导致退化的默认入口、轻量编辑壳、自动提示/只读配置 | 从默认玩家路径撤下，回接旧路径；保留必要对照记录 |
| 不破坏旧体验的局部修复 | 经差异审查和回归后保留，例如可用的错误说明、对照展示、翻译修正 |
| 未验证的大结构变化 | 本轮不推广；保存但不作为默认产品，不继续打磨八关壳 |

不维护第三套编辑器。临时保留新版用于恢复和比较，不等于长期维护两条主线。清理无用实验代码是以后有证据的独立任务，本轮不自动删除。

### 6.3 技术不变量

可见拓扑与实际已应用程序决定执行；Trace/指标同源；播放、窗口和线条几何不改变仿真；普通线与接点零延迟；缓存自动管理；本地 telemetry 不决定进度；Game/Test 严格隔离；旧自建组件来源和依赖验证不伪造。

暂不统一三种模拟领域，不改变位宽、ISA、缓存语义或存储提交时序。也不在恢复期间顺手改成另一套“应用/执行”机制；先保持用户可识别的现有操作。

## 7. 安全恢复办法

本地修改未提交时，“退回旧版”不能等同于 `git reset --hard`。

Codex 先检查当前 HEAD、暂存/未暂存差异、未跟踪文件、正在使用的场景入口，以及新旧存档实际路径。建立可恢复的备份：未提交差异、二进制/新增文件、相关玩家数据；只一份 Git patch 不会自动覆盖所有未跟踪文件与 `user://` 数据。

备份放在不被本次修改覆盖的位置，记录范围并核对。区分用户已有修改与本轮生成修改，无法安全分类的内容先保留。不要默认备份无关敏感数据，也不要把存档备份推入远端。

对照提交 `d7aa2f1` 是候选起点，不是必须整仓回滚的命令。禁止破坏性清理、擅自 commit/push、覆盖用户文件或清除旧存档。新版独立存档也保留，不默默映射成旧构建已验证。

## 9. 必须能从真实入口复现的验收动作

功能测试可使用参考电路作 oracle；以下体验检查则必须走正常 Game 的 UI 输入路径，不能直接注入标准答案或用内部方法绕过操作。

| 检查 | 操作与通过依据 |
|---|---|
| 入口 | 导出 EXE 的“开始/继续”进入恢复后的原序章/路径，不是旧场景的开发快捷入口 |
| 任务 | 进入关卡立即看得见目标；关闭/收起后可重开，仍可查看先前页与规格 |
| 编辑 | 主体选择/移动，放置，删线、擦除，撤销重做；结果同时反映在图与真实模型 |
| 分支 | 在 Half Adder 已有线上间处分支到另一个兼容输入；接点可见、交叉不误连、可撤销 |
| 状态恢复 | 从文本框、手册、Hint、回放回到画布后，可继续编辑，不残留输入锁 |
| 提示门槛 | 默认无解法；H1→H2→H3 必须逐级主动请求；完整答案有明确确认；不能意外越级 |
| 提示隔离 | 离开各级提示后方案名、拓扑、位置、线色一致；没有注入参考连线或通关 |
| 测试结果 | 失败指出具体用例/状态；正式通过给显眼后续操作，不自动切走 |
| 变换 | 缩放/平移、窗口/全屏后，端口、落点、擦除和分支命中仍正确 |
| 数据保护 | 老存档、命名方案、已验证来源和依赖关系能够恢复；新增八关存档未被删除 |
| 导出 | 构建带唯一标识，说明基准/dirty 状态；被验收入口与打包入口一致 |

Headless 测试可以覆盖大量输入状态，但不能代替真实平台的鼠标舒适度与高 DPI 观察。只写实际测过的分辨率/缩放/平台；没有实机就明确未测。自动化通关、真人理解、个人趣味是三种不同结论。

本轮不追求“新人一定喜欢”的宣言，最低可交付条件是：用户从正常入口确实拿回原有操作，任务清楚可找，提示在其主动选择之前不剧透。

## 10. 文案和手册的增量统一

统一任务、规格、反馈三种用途，不做全仓库无差别改写。先修本轮涉及的可达字符串，检查中文和英文是否在相同位置表达相同规则。

| 不合适 | 合适的方向 |
|---|---|
| 本关将引导你掌握控制逻辑 | 按指令把参数送到正确位置。 |
| 请完成当前设计 | 明确所需输出/状态与测试目标，不能只写一句空目标。 |
| 拓扑签名与行为契约已绑定 | 已保存为全加器，后面可以直接使用。 |
| 一进关卡就写完整连接方法 | 主任务只给规格，推理关系进入逐级提示。 |
| 连接无效 | 位宽不匹配：4 位输出 → 1 位输入。 |

不删必要技术信息来追求短。术语首次出现有解释，后续稳定使用；保留技术标识与清楚中文说明。技术准确性检查以实际模拟行为为准。

## 11. 交付要求

交付应包括：旧能力恢复对照表、每项已复现退化的原因、修改文件范围、相关回归结果、普通 Game 实际操作证据、可试玩包位置、构建标识、未验证内容。

不要只写“19/19 或更多测试通过”。必须说明测试是否真的走了默认入口和真实编辑事件。不要说“已完全修复新手体验”而没有相应真人测试。
