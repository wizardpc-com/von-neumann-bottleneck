## 逐关评估

符号说明：**保留**＝已有清晰的新发现；**加强**＝机制值得保留，但表达或节奏不足；
**优先**＝认知跨度、重复或成果用途值得重点验证。均为设计判断，不是玩家统计。

| 关卡 | 玩家真正要发现或决定什么 | 趣味与当前风险 | 建议及边界 |
|---|---|---|---|
| 接线教程 | 反相、连接关系，以及编辑错误可以修复 | 加一根线就看到灯变化，反馈直接；删线再接回是操作练习，不宜反复强制 | 保留五项规则；先修拖动、中断与预览，明确下一步可做动作 |
| 半加器 | 两个输入的“不同”和“同时为 1”如何组合 | 第一处真正的多解构建，封装有所有感；从 NOT 直接跨到多门组合，对新人跨度较大 | 保留自由解法和完整四行测试；可选应用关方案见下，不能直接塞入默认答案 |
| 全加器 | 把自己的半加器和来自低位的进位组合 | 复用成果有意义；两页规格重复，容易照预摆位置接线而不理解进位 | 加强“这次多了什么”与 1+1+1 的反例意识，保留 8 行要求 |
| 一位 ALU | 区分计算数据与选择运算的控制信号 | 同一电路做四件事有新意；5 个输入、MUX 和 32 行测试集中出现，容易变成找端口 | 优先：分组呈现观察重点；拆出必经选择器关会改前置，须批准 |
| SR 锁存器 | 输入相同，历史不同，输出也可不同 | 第一次“记住过去”很有发现感；反馈回路和禁用 S=R=1 需要准确解释 | 保留两次保持的对比；文字明确 S、R 是控制端口，不能写成固定输入值 |
| 一位寄存器 | 把“置位/复位”接口改成“数据/允许写入” | 复用锁存器而改变使用方式，是有价值的新抽象 | 保留；突出 LOAD=0 后改变 D 的实验，不默认给 S/R 接法 |
| 2×4 RAM | 地址同时决定写到哪里、读出哪里 | 两个独立位置让状态可见；一下加入四位数、Decoder、Word MUX，术语负担较高 | 优先：用两个不同值的读回来说明不串写；新的寻址练习关须批准 |
| 四位累加器 CPU | 用控制信号组织已经做好的算术和存储 | 汇合两条分支是强里程碑；19 根连接、多个模块、四条指令同时出现 | 保留关内 A/B/C/D 与独立 Hint；接口接齐并不代表行为正确，反馈必须区分 |
| LOAD/STORE | 使用自己封装的计算机，看 ACC 与 RAM 各在何时改变 | 成果终于运行，但正式七步与 CPU 重复，单纯再点一次运行的新发现弱 | 优先：加一个不计分的观察问题；若改成可编程应用关，须批准 |
| 1-1 接通第一台系统 | 计算、存放与传输分工；实际显示路线决定执行 | 六条系统路线比细门电路轻；刚造完四位 CPU 又换成独立八位模型，所有感可能中断 | 明说模型边界，减少“继承了原电路”的错觉；贯通两个模拟领域属于重大架构改动 |
| 1-2 CPU 变快以后 | 单个部件提速与整机提速不成比例 | 预期被数据反驳，值得保留；只有两款 CPU，改动本身几乎没有解谜 | 保留受控实验；重点是解释差异，不再要求重复建同一套路线 |
| 1-3 CPU 在等谁 | RAM 响应时间会改变 CPU 等待 | 与前关同一程序形成对照；流程又是预测→运行→换件→运行，易机械重复 | 加强承接前一关的疑问；若跨关继承有效对照结果以省一次运行，需单独核对证据规则 |
| 1-4 一字节要走几次 | 通道宽度改变分段数，与响应等待不同 | 从求和换成搬运，问题有区别；宽度名称如果已透露结论，预测会像填问卷 | 用可见分段和总时间区分运输成本，保留宽/窄比较 |
| 1-5 瓶颈调查 | 在不同规模上用证据判断主因 | 第一次综合诊断；默认配置的正确项固定，若不看证据也可猜中 | 保留诊断后揭示；随机或多场景诊断会改变关卡判定，须批准 |
| 2-1 为什么每次都要走那么远 | 同样取数为何反复走 RAM 路径 | 作为全新章的观察入口直观；与第一章等待主题重叠 | 明确新问题是“能否避免下一次远途”，不是重新介绍 CPU WAIT |
| 2-2 把它留在近处 | 自动 Cache 填充使后续请求命中 | 第一次用 Cache 产生明显收益，且能继承上关有效基线 | 保留；说明哪些数据自动留下，不能让玩家手工安放缓存内容 |
| 2-3 它为什么没有帮上忙 | Cache 已存在，却在复用前发生替换 | 对“加硬件总会快”的反转有新意 | 保留观察→证据判断；先看访问轨迹，术语在需要时开放 |
| 2-4 换个顺序 | 硬件不动，访问顺序也能改变成本 | 两层循环顺序交换给直接可见收益，是第二章最强的行动关之一 | 保留编辑与 Apply 边界；确保变化能在地址序列里看见，目标仍为 105 周期 |
| 2-5 明明顺序已经对了 | 一轮内复用和跨轮复用是不同问题 | 从局部性转向工作集容量，反转合理；必须清楚第二轮为何是新证据 | 保留两轮对比，避免重讲首轮的概念 |
| 2-6 一次别做那么多 | 把两轮工作安排在同一小组数据仍在近处时 | 时间调度改变工作集，有新的优化维度；如果只是切一个选项，探索空间偏窄 | 保留 145 周期与现有 Work Group；新增手写分块程序能力须批准 |
| 2-7 现在，自己调查 | 组合已有观察、诊断和软硬件策略 | 多种解法值得保留；仍用熟悉的 4×4 两轮任务，作为终章的新鲜感有限 | 优先：准确说明先单因素、后组合；新增不同负载/预算的收尾任务须批准 |

## 可批准的最小玩法试点：可选“三路表决”

建议先做一关，验证“使用自己的成果解决新问题”是否值得扩展。

- 入口：完成全加器后，在该成果旁开放可选挑战；不作为 ALU、CPU 或任何原关的新前置。
- 情境：三个开关代表三路确认信号，至少两路同意时点亮输出灯。
- 输入：A、B、C，各一位；输出 VOTE，一位。无时钟、随机性或新仿真机制。
- 正式测试：000/001/010/100 → 0；011/101/110/111 → 1，共八种输入。
- 自由构建：允许已有逻辑门以及玩家封装的 HalfAdder/FullAdder；不用提示自动接线。
  一个值得发现的关系是加法的进位也能表达“至少两个输入为 1”，但不在任务页透露。
- 成果：独立可选完成记录，独立三级 Hint；不授予新的必需元件、不修改旧关成绩。
- 必须先批准的变化：新增关卡 ID、可选入口、正式用例与完成记录。实施时需独立执行计划，
  验证旧玩家进度与原 9+5+7 路线不受影响，再原生试玩并单独提交。
- 首轮验收：尝试门电路与复用模块两种解法；检验错误输入的反馈；让真人新手说明
  “为什么这次使用全加器与计算 SUM 不同”。自动通过不能证明挑战有趣。

暂不建议同时增加强制 MUX/寻址关或改造第二章终局。先评估这个小试点的体验，
再决定是否扩展。跨关成绩复用、存档稳定指纹及旧模板注释兼容属于另一项数据边界，
仍等待批准；本轮仅修正呈现与交互。

| 四路择一 selector4 | 分层选择或译码组织 | 64 组合规格、空白内部、不同结构均按行为判定 | 本轮自动回归；新手负担未知 |
| 报警别消失 alarm | 瞬时事件、保持、清除优先 | 不用接线形状判定；与原锁存器保持独立可选关系 | 本轮自动回归 |
| 错了一位 parity | 额外一位能检测什么、不能检测什么 | 公开检测边界，不宣称纠错；保留不同 XOR 组织 | 历史原生32/32；本轮自动回归 |

| 两张订单 two_orders | 一笔预算对应不同瓶颈 | 每张订单独立方案/真实成本，不按指定零件给分 | 本轮自动回归；难度还需外部样本 |

| 慢一点 backpressure | 消費前不要覆盖 | 变化算时打破固定等待，状态反馈有实际用途 | 历史原生；本轮回归 |
| 提前一点 prefetch | 提前取但仍共享传输通道 | 复用上一关知识，不引入新CPU/内存模型 | 历史原生；本轮回归 |
| 不是越早 distance | 太远的预取会替换、重传 | 保留无重复传输附加挑战，区别基础过关 | 历史56→30；本轮回归 |
| 别让计算停下 synthesis | 两条时序能力汇合 | Cache/缓冲两路保留，任务树显示真实双前置 | 历史另一Cache路线；本轮回归 |

### 本轮产品打磨的共同动作

- 扩展原任务树到五区；缩远看区域和真实完成数，点击区域定位下一可玩任务。不会把缩远时没有画出的节点记作已经曝光。
- 保留任务全文侧栏与锁定原因；第四章与第三章同从第二章综合任务分叉，不画成第三章之后才解锁。
- 新章工具默认打开；新功能先在该关规格中介绍。首屏开始按钮、复制选项、中文错误/记录、批次筛选、源/副本切换针对实玩问题调整。
- 新章 Hint 仍为独立只读视图；H2只给局部字段关系，H3完整方案需确认，普通布局不被提示改变。
- 不用上述开发者判断给所有关卡填“趣味分”。外部新手的困难、喜欢与流失原因由逐关评分、意见及准确访问记录收集，缺失不补零。
