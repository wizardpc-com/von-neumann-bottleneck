## 九个重点节点的可执行设计

### 1. ALU：先辨认控制，再搭多操作机器（P1）

问题：“A、B 没变，怎样让同一台机器执行不同操作？” Mission 首屏保留四操作规格，按数据 A/B/CIN 与控制 OP0/OP1 分组。增加可忽略的“先试谁能通过”入口，调用现有 TaskNavigation 去 selector；离开前使用现有草稿保存。未完成 Selector 仍可做 ALU；不把它封装为新强制器件。

调试建议固定 A=1、B=0、CIN=0，逐次选择 OP；这是测试建议，不能注入参考电路。正式32行仍全部执行；失败列表先显示失败的操作组，再展开输入行。非加法操作 CARRY 未定义的现有判定不能被显示成必须为0。

验收：控制端错误能定位至选择操作；算术错误能定位至数据结果；四操作等价自由接法均有效。Hint1 只问“每条计算路径的结果由谁选择”，不画完整 MUX 接线。

### 2. RAM：让“没有被改动”成为看得见的结果（P1）

沿用当前五步官方程序，不增加必经寻址关。将实际观察值呈现为逐步状态记录：写0=3、写1=12、读0、改0=5、读1。只在该步真实完成后追加结果；若当前仿真结果未提供两寄存器的可信快照，只显示已观测读回值及时间，不伪造隐藏状态。

玩家先决定读回哪个位置进行调试。反例用错误的写使能同时连接两寄存器，展示读0已变12；另用读选择反接检验写入与读出责任不同。不要把第二次写入就自动解释成“现在两个地址独立”。

验收：玩家能指出最后读1为何还是12；错误写/错误读可区分；正式五步、奖励 RAM2x4 和来源签名规则不改。

### 3. CPU：保住“这是我造的”这一刻（P1 POLISH）

复用现有 A/B/C/D 和七步程序，不再追加新教学向导。首次通过后允许在原 Trace 上回看 LOAD_IMM、ADD、STORE、LOAD 的差别；强调自有 ALU4/Register4/RAM2x4 的名称和来源。完成弹窗不给整屏世界观。

候选短句：“这些部件第一次按同一组指令工作。”进入第一章时说明模型扩大为8位系统成本实验，继承的是经验证的来源，不声称测量原门电路的真实速度。

验收：返回再进、读取历史 Trace 与封装均不重复授予进度；自己的模块名可见；一次失败不清掉编辑成果。

### 4. LOAD/STORE：从再跑一次改为一次状态实验（P1）

第一阶段只重排观察焦点：用现有七步中“STORE 0=3 → ACC 改成5并加2 → LOAD 0回到3”问“改变当前数值，之前保存的值也会改变吗？”不计分预测、可直接运行、不增加阅读门槛。正式通过仍使用原七步。

第二阶段原型才考虑一个独立的练习指令条（不替换官方程序）：LOAD_IMM 6 → STORE 0 → LOAD_IMM 2 → STORE 1 → LOAD 0 → ADD 3 → STORE 0 → LOAD 1。预期 ACC依次6/6/2/2/6/9/9/2，最终地址0=9、1=2。这是外部指令序列，**不是增加取指器或 PC**。先在现有模拟器校准再决定是否成为正式内容，不能改 `_computer_program()` 同时偷偷改变 CPU 验证。

验收：操作自己封装的 TinyComputer；用不同合法数值重复；STORE 前后分辨 ACC/MEM；原存档来源仍可重验证。此轮只交规格，未替换正式七步。

### 5–7. 第一章：把三个同构流程改成三个不同问题（P1）

| 节点 | 核心动作与转折 | 必须留存的证据 | 完成条件边界 |
| --- | --- | --- | --- |
| cpu_speed | 先预测整体收益，再仅换CPU；对照两段计算短了、等待仍在 | 现有两正式案例；同尺度时间图；316→268与等待252是当前模型的参考，不写在任务题干 | 不考预测对错，不增一轮运行 |
| ram_wait | 承接上关Fast结果的疑问，沿请求→RAM→返回定位，再换RAM | 重新在目标关运行可重放的基线配方；268→124、等待252→108 | 新关 case 名与签名不同。原receipt不能直接复制；重放验明来源/拓扑/程序/数据/模型，再生成本关receipt。缺失时走原路径 |
| bus_width | 让玩家预测“传输四倍是否让整机四倍”，再观察 | 4→1分段、64→16传输周期，但总144→96；同步时间尺度 | 两种硬件仍需官方通过；不隐藏公开带宽，不改成本 |

先改善观看节奏，再做 receipt 承接。承接实现涉及 `system_lab.gd`、`system_chapter_state.gd`、`SystemRunReceipt` 与 `ChapterWorkspace`，单独工作包并补错误来源、旧模型和重启测试。不得自动解锁，也不得强制重放所有动画。

将 Read Once 作为 ram_wait 后的推荐岔路，给愿意写程序的玩家一次主动修改机会；Two Orders 保持可选，承担“同一配置不是普适答案”的迁移任务。这样缓和重复，不需要删去受控实验教学。

### 8. 2-6：把唯一按钮变成可反驳的猜想（P0，本轮试点）

固定一行 Cache、按行访问、两轮和145目标，开放现有0/1/2/4组。0是原两整轮；非零是每组先做完两轮。给出控制含义，不透露获胜组大小，不强制试完全部选项。正确但慢与结果错误分开显示。

预期实验：两行组看似减少切换，但跨轮要再次取回；一行组在离开前完成两次使用。真实模型计算为：0/2/4组均210周期、8miss；1组138周期、4miss。测试确认大组不能解锁 Blocking finding，小组仍须原先的播放/复盘边界。

这是一次有限选择的概念实验，**并未变成多解优化关**。不加虚构的“分组管理费”迫使大组偶尔获胜；容量与组大小真正的多解关系留给2-7的硬件选择。工作组面板增加局部滚动，避免四项占满小窗口。

### 9. 2-7：先让当前终点诚实，再做知识迁移原型（P2）

当前为4×4两轮求和，并非陌生任务；第一项小修是把“新任务”改成“独立调查”，保留第一次单因素、之后组合的现有门控。通关后并列展示自己实际跑过的周期/成本，不补造未运行的赢家记录。

校准24种组合可验证它并非只有同一解：1行Cache+1行组与4行Cache的138周期解成本不同；2行Cache+2行组也可探究容量配合。现有经济方案附加目标应醒目但不升为主门槛。

真正陌生 workload 不能只换16个数：当前核心固定4×4、16值，数值改变不改变地址成本。也不能把它轻易改成6×6而忽略 parser、调度、案例签名、UI地址网格和存档重放。

建议先制作**独立开发原型“同一预算，两种访问”**：订单A为现有两轮完整扫描；订单B为重复访问两个不相邻行的热区，要求合法输出与每行访问次数。固定硬件总预算、允许访问顺序和组大小，要求同一配置服务两单。原型先明确 DSL 能表达的受限循环/地址范围，生成至少三套非参考解与“盲用旧方案”反例；目标依据真实枚举后再定，绝不先写145。若表达此 workload 需要扩大 DSL，本轮暂缓，不以伪装的数据变体代替迁移。

发布选择：只有原型证明有新的决定，才增加一个可选节点或独立变体。保持旧 capstone ID/目标/进度有效，新案例使用独立内容版本；不得旧ID下替换用例后让老存档无声退关。

## 声音与视觉：先做两关的可验证原型

### 接入现实与最小结构（P2）

新增候选 `src/ui/trace_ambience_profile.gd`（纯区间归一化）和 `src/ui/trace_ambience_player.gd`（场景拥有的播放节点）。名字是计划，不是已实现文件。不用 autoload 全局指挥器、事件总线或改 simulation。由各章 UI 提交 Trace 的只读区间副本及当前播放位置；换关、失效结果、暂停、结束、焦点丢失时停止/淡出。首个覆盖 cpu_speed 与 buffers，通过后才扩 locality。

| 域 | 权威源 / 映射 | 边界 |
| --- | --- | --- |
| 序章 | Circuit/Prologue事件是逻辑与呈现步骤 | 不把 settle/visual step 当真实耗时；暂只保留短完成音 |
| 第一章 | compute→计算；ram_read/write→服务等待；read/write_data→数据搬运；request→控制 | `cpu_wait`覆盖RAM+Bus，不能再把它与两者相加计时 |
| 第二章 | compute、ram_access、实际传输/返回事件按其kind和duration映射；hit/miss仅注释因果 | 逐类核对事件可能包含的重叠区间；不对每个hit播放提示音 |

使用当前播放周期附近固定模拟窗口，例如8周期，计算 compute/transfer 的区间并集长度与二者交集；比例各自0…1，不要求compute+transfer=1。未工作的时间与等待按域明确区分。零时长诊断/缓存事件不当作持续忙碌。实时平滑用0.8–1.5秒攻击/释放，窗口参数只属于音画，不参与验证结果。

播放速度只改变游标前进，不直接提高音高；拖拽到历史步骤立即重置包络并短淡入，禁止补播跳过的几百个事件。程序编辑后旧Trace仍可查阅，但必须标明历史并停止当前运行氛围。回放可以跳过，不以听满音乐授予结果。

### 听感约束

一层安静底音、一个计算声部、一个搬运纹理足够。统一音色素材与和声，不按“正确/错误”切大调/小调，不把繁忙=快乐、等待=失败；等待是任务本身的一部分。双缓冲只在交集存在时让两个声部同在。禁用蜂鸣、每事件瞬态、强低音和突然掉到绝对静音。

先用相同音量下的短循环素材做占位原型，后续可换正式授权素材；不宣称合成音已经达到最终音乐品质。Music/Ambience 需要独立音量与静音，默认低于当前完成音；保持Effects与现有设置兼容。减少动效只约束视觉，另提供“声音动态减少”，避免把视觉偏好擅自等同静音。

测试：相同Trace播放/静音/倍速/暂停/seek/关场景前后 canonical_signature、metrics、receipt、进度必须逐项相同；音轨只由拷贝区间驱动。连续多次运行不会叠加播放器；后台和退出不残留声音。真人耳机/扬声器试听是独立门槛，不能拿自动测试证明“不刺耳”。

### 视觉约束

保留现有仪表与 SignalNotation 的宽度色，不重设一套电线颜色。计算用部件内部轻脉动、等待用稳定状态标记、搬运沿真实连线呈现；并行用两资源时间条的真实交集。位置章突出实际源/副本地址与准备阶段，不增装饰性“更远更慢”电线。减少动效保留静态标识和数字；任何语义不能只靠颜色或声音。

对照时共享同一时间尺度，避免两次运行都拉满同样宽度导致“看起来一样快”；玩家可选择结束回放。音画是证据的第二种读取方式，不抢 Mission、正式失败或操作反馈。
