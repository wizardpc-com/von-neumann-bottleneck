# 叙事与体验交接

本轮由主控逐项审阅来稿并修订最终文字。子任务提供任务映射、技术事实与代码风险核查；
它们的表格不是自动采用清单。运行证据与60关审计见
[核验记录](../verification/20261021-narrative/README.md)。

## 文案取舍

| 来稿的有效方向 | 本轮处理 |
| --- | --- |
| 从一根线、一次真实运行开始 | 初次邀请和NOT步骤卡直指操作；不用雕像身世阻挡第一步 |
| 01-2 将和与进位分开解释 | 保留具体二进制例子，去掉无依据的“进位更慢、更贵” |
| 02-2 算得快与整机时间要分别观察 | 让玩家完成两份受控记录；不预告“总时间没少” |
| 03-4 只改顺序再比较 | 明确应用程序、正式目标、命中与取数；不把线长当访问代价 |
| 留下失败与比较证据 | 章末回到记录与下一次实验，不批评玩家依赖答案或谨慎试探 |
| 09-2 规律本身也要发送 | 保留这个事实；拒绝同卡结算中“规律不占包”的相反说法 |
| 11-3 为作品命名并保存 | 只有原保存事务成功才回应；使用本地作品墙与配方分叉 |

没有照搬“比你想的贵”“现在你学会节制”“这比最好更难得”之类评价。
壹不替玩家宣布审美、心理或普遍结论，也不把未测过的性能变化说成已经发生。
通关反馈只对应当前任务，不宣布所有分支已完成。两种语言表达相同边界。

来稿 `05-5`、`06-3`、`06-4` 正文与实际关卡差异过大，映射表把它们标为
**槽位候选**，用于与作者讨论重写，不代表语义已经匹配或文字可直接发布。
其余对应也只确认任务归属，具体台词仍以审计意见为准。

## 给 Claude 的视觉与交互精修边界

先看本轮1280×720中英实机渲染，重点检查终端顶栏“返回”、短问答与主菜单的切换、
半加器任务台的信息密度、CPU/访问顺序证据与G3保存状态的可见性。
尽量复用现有控件，保留“打字时也能走”、操作后开场提示离场、减少动效和键盘焦点。

具体视觉待办：半加器完整说明在720p仍需滚动，英文页签会换行；
创造工作台英文顶栏章名使用省略号，完整任务名仍在其下选择栏。
可调整信息层级与可用阅读空间，不通过删除规格或隐藏保存失败原因减轻密度。
CPU英文完成状态撑宽界面的问题已用一句短提示修正，窗口宽度纳入新增检查。

不能把地图中全关可访问的QA夹具当作玩家已通关。不能从档案读取或对话选择赋予
完成状态、模型能力、作品或规则。作品截图来自真实生成/保存；实验室作品回应与
锁定档案的展示截图会明确标为呈现夹具。

弥拉、洪水、雕像、钥匙、旧档案人物、壹的身世与最终尾声仍需主创确认。
本轮没有制作公开发布包，也没有合并远端main。
