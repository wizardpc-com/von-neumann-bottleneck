# Real-player feedback rollout

2026-11-22 · Source audit of `66e1bf0a1ee7e4f99a48b847401dfdab2ff6eddd` and the shared checkout. The four frozen Game/Test packages are an internal baseline. The target player path is **Feedback → type → Send** from an unfinished task, with a visible receipt on delivery. Gameplay and local drafts work without a connection. An invite-only Windows x86_64 and macOS Universal pilot, a separate save profile, and limiting the pilot to opinions are proposals for the first rollout.

## Smallest implementation sequence

1. **Make the report action discoverable.** Implemented in this checkout. Existing shared workbench buttons appear when the receiver is configured and open the task with the opinion field ready to type. Send has a short disclosure and a link when a supported privacy URL is configured. **Save on this device** leaves the opinion local. The form displays the receipt ID only on matching acknowledgement. F8 and the offline capture and export routes remain available. The focused [UI regression](../../tests/test_playtest_feedback_ui.gd) exercises the button, both languages, local save, queued delivery, mismatched and matching acknowledgements, and the no-receiver fallback. Toolbar fit and focus in native workbenches await runtime verification.
2. **Prepare a cross-platform build profile if a pilot proceeds.** A distinct, stable save profile shared by both pilot platforms would preserve separation from existing QA and player identities without migration. Test provides all entrances. Game preserves earned access for first-time progression studies. Either uses the existing Windows and Mac export presets and an explicit frozen build identity. The candidate checker, package notes and locked workbench profile gates must agree with that identity. Stamp the selected endpoint, privacy URL, full SHA and batch and set the player build's default source to `external_player`. Mark scripted preflights `automated` and keep their batch distinct. Source and batch are client-supplied report labels. Validate build combinations and record the external acceptance receipt separately from artifact generation. [Builder](../../scripts/build-free-candidate.py) · [Identity checker](../../scripts/check-candidate-identity.py) · [Profile gate](../../experiments/layout_strategy/lab.gd) · [Packaging regression](../../scripts/test-candidate-packaging.py).
3. **Keep consent as short as the selected offer allows.** The existing **Send** already provides per-opinion opt-in. If the pilot is limited to opinions, skip the startup statistics prompt, omit statistics and score choices for that profile, and guard transport setup and restore against enabling those channels. Keep drafts, retries and confirmed deletion reachable. The same allowlist, outbox, SQLite API and report can carry the opinions. Verify the independent local-action preference fix across restart. A policy or destination change on a shipped profile must account for previously queued opinions and deletion access. The existing restore path loads the queue only when notice and destination match.
4. **Exercise the whole handoff privately.** Use the existing receiver and report with temporary data and an isolated client profile. Document a two-step operator workflow. Look up a player's receipt in `received_feedback` by ID and check task, mode, SHA and batch. Then triage privately by that ID using the sidecar. Use the existing daily report refresh and explicit post-deletion refresh. Offline evidence, if requested by the operator, goes through the existing ZIP import rather than the opinion endpoint. For a first pilot the JSON/HTML report already supplies the necessary fields. Report review should check the approved batch/source in addition to the receipt, including rows marked with a content/version mismatch.

## Acceptance order

- **Local engineering and QA.** Use isolated profiles and synthetic data to test the UI, preferences, builder and operator workflow. For runtime QA, run `test_playtest_feedback_ui`, `test_settings_feedback_layout`, `test_prelaunch_settings`, `test_offline_feedback` and `test_remote_feedback` through the [isolated verifier](testing.md). When packaging is in scope, validate both manifests with `scripts/test-candidate-packaging.py` and `scripts/test-package-feedback.py`, then use the [local package harness](../../scripts/verify-package-feedback.py) on both exports. Verify the final embedded settings independently of any endpoint or profile overlay.
- **Client gates.** In both languages, open from a real unfinished task by mouse and F8, with no stats or scores enabled. Check the task and inline disclosure, cancel or Keep Locally with zero upload, then Send once and see the matching receipt. Start offline, type and close, reopen the draft, send offline, quit immediately, restart and reconnect. Check one stable receipt and one committed row after exact retry. Exercise unavailable receiver, wrong/incomplete acknowledgement, permanent rejection, and manual retry in a temporary fixture. Show a clear pending/failure state and confirm the local draft is still usable. Confirm withdrawal and confirmed deletion through the same identity, plus operator report refresh and removal of the matching receipt and stale triage. Check minimum window size, keyboard focus return, unsent drafts in both locales and offline Test ZIP capture/export. See [transport tests](../../tests/test_remote_feedback.gd) and [report tests](../../server/test_private_report.py).
- **Operator-authorized external preflight.** From normal downloads on native Windows x86_64 and macOS, record clean-profile launch, package hashes, platform/signing prompts, embedded URL, normal OS TLS, and representative independent network reachability. Include Intel Mac if that support is being claimed. Use distinct synthetic rows as technical controls and verify deny routes, exact retransmission and deletion before accepting actual notes. Then have consenting invited players on both OSes independently discover the action, leave one real opinion, see receipt, and continue play. Check the exact ID privately in the report. Capture time/actions to find Send, eventual status, and any assistance needed. Record actual OS/network coverage and separate synthetic, operator and player observations. The existing /32 Mac control does not cover these gates.
- **Pause and rollback.** Stop inviting or distributing the online pilot if new-player discovery, receipt matching, deletion, or availability fails. Keep the offline packages available for fallback within the authorized cohort. The operator can withdraw the dedicated 8443 rule or stop the independent public unit without changing shared services. A paused endpoint also blocks in-game deletion and delays pending opinions. Retain the receiving library and valid tombstones, keep a private deletion contact available, and restore access under the approved retention policy. Never use an older SQLite snapshot as a shortcut to rollback.
