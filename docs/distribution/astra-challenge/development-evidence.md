# Development evidence, without overstating it

This is an existing game, iterated with ChatGPT/Codex. Do not describe it as a game made from scratch during the challenge week, or claim every commit was generated by Astra.

| Public evidence | What it establishes |
| --- | --- |
| [Repository history](https://github.com/wizardpc-com/von-neumann-bottleneck/commits/main/) | Incremental implementation and reviewable changes |
| [Architecture](../../../ARCHITECTURE.md) | Deterministic models separated from rendering; no inference service required to play |
| [Native follow-up](../../verification/20260914-native-followup/README.md) | Recorded source-native player actions, outcomes, and limitations |
| [Verification workflow](https://github.com/wizardpc-com/von-neumann-bottleneck/actions/workflows/verify.yml) | Reproducible automated checks, not novice acceptance |
| [Current candidate](../../CURRENT_STATE.md) | Exact content identity and remaining platform gates |

For the competition's model-use explanation, the owner should select one or two real Astra sessions showing a concrete prompt, reviewable change and verification. A commit hash alone cannot establish the model identity. Redact private paths, logs, identifiers and unrelated conversation before choosing what to share; do not share a whole conversation automatically.

Suggested structure for the owner to complete:

1. The problem I brought to Astra: [specific example].
2. The part it helped implement or review: [commit or diff].
3. What I rejected or corrected: [actual decision].
4. How I checked the result: [test and visible player action].

The game runs deterministic local simulation. It is AI-assisted development, not an AI-powered runtime, AI tutor, or automatic solver. Describe Windows/macOS support only to the extent established by final package checks.
