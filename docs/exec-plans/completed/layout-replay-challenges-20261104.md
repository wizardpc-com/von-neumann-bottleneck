# Replayable scheduling challenges

Implementation and bounded runtime acceptance complete. Git delivery follows
the user's separate authorization and is verified after the milestone commit;
passing tests alone do not establish a push or release.

## Goal and scope

Make the existing four-workload scheduling lab support an actual challenge loop:
share a measured recipe with fixed objective/caps, preview and locally remeasure
a code, explicitly accept its target, then improve and compare under those exact
rules. Retain one target per workload in a separate protected experiment file.
Fix numeric edit → Cmd/Ctrl+Enter so the visible committed value is measured once.
Root owns design, integration, Git and sequential Godot runs.

This does not add workload definitions, change the model/costs, alter Notebook v1,
change the formal `VNB4C1` protocol, award campaign progress, run a server or claim
global optimality/online anti-cheat. Main and ordinary player data are protected.
User authorized significant verified commits/pushes to the task branch.

## Audit and decision

The fresh unchanged-model probe executed1475 candidates and48 repeated/JSON
Traces with no failures. Two serial scans have competing sample metrics:
direct Q1/total/RAM/copy307/614/544/0 and copied557/672/500/80. Changing the
objective under Q1≤600/copy≤80 chooses different sample winners. This is evidence
for later structural workloads, not a new shipped task or a global optimum.
The physical mapping probe retained the prior5/2/7/2 frontier classes; a separate
1140-evaluation copy-block probe also found no novel combined frontier tuple.
Extra physical-layout controls are therefore deferred.

Three independent audits favor the bounded challenge loop plus numeric input
repair. Structural workload changes need condition-scoped state/compatibility;
replacing data behind the current fixed IDs would protect existing notebooks as
stale. Preserve that work for a separate plan.

## Contract and compatibility

- New `VNBSC1:` transport, ≤4096 UTF-8 bytes including prefix/clipboard whitespace.
  Exact envelope `v/task/model/condition/goal/plan`, strict canonical JSON.
  Goal binds total cycles or RAM traffic and inclusive Q1/copy caps.
  Inputs only: no claimed scores, identity, timestamps or executable payload.
- Decode retains structurally supported stale model/condition identities; inspect
  requires current full condition, correct complete output and target eligibility.
  No-copy transport normalizes dormant copied fields/layout to starter defaults;
  the notebook's editor choices remain untouched.
- Preview and accept leave draft, Undo/Redo, selection, personal goals and kept
  plans unchanged. Confirm re-inspects actual code under current workload.
  Target restore is an explicit one-Undo edit. Attempts compare actual same-
  condition measurements against the target's immutable goal, independent of
  personal filters: unavailable/outside limits/behind/tied/improved.
- Two opt-in starter targets use ordinary direct-source recipes, remeasured by
  the same codec. Known beating recipes remain test fixtures, never prefilled
  solutions or default rankings.
- `layout_strategy_challenges_v1.json`, ≤32KiB, one canonical code/workload,
  maximum4. Notebook and target file are separate transactions. Explicit target
  accept/clear/retry controls save only targets, with saved/temporary/protected
  status. Failed writes retain the exact proposed map, including pending removal.
  Whole-file UTF-8/schema protection, dedicated cooperative writer lease,
  random temporary file, readback/digest validation and atomic rename.
  Supported old codes remain copyable but inactive.
- Rollback disables the new reader/UI and leaves its sidecar bytes untouched.
  Old code still reads the unchanged notebook; formal saves/targets are untouched.
- No UI/render timing affects simulation. Sharing remeasures inputs; a display
  label or imported number is never score authority. Persistent input files
  are not proof against a modified client.

compatibility/rollback design. No release is authorized by this plan.
