# 章末回应与下一条路线

第二章的章末回应现在明确告诉玩家：回到终端，打开「旅程地图」选择搬运时机或数据布局路线。原句“你想先试哪一边？”出现在只有「回到终端」按钮的一页，容易让玩家寻找并不存在的路线选项。修改保留两条探索方向，只调整这一句中英邀请，没有新增按钮、对话分支或故事事实。

路线依据是 `TaskNavigation` 的依赖映射：`chapter_3/arrival` 和 `chapter_4/fields` 都接在 `chapter_2/capstone` 之后；两个章节的原开启条件也读取 capstone 完成记录。

英文实际回放还发现就近存储面板的问题：在720p下，文字和三张选项卡把不带滚动的内容撑出了工作区。四行缓存选项画在工作区下方，点击却没有改变容量。该面板现在与其他工具一样使用现有滚动容器；选项内容、容量、成本与判定不变，玩家可滚动到四行选项并正常应用。这项修复补齐了此前画布高度调整的交互边界。

## 实际操作验证

新增 `test_chapter_return_input` 在独立存档的Test模式进入第二章综合任务。进入权限是测试前提；之后通过Viewport鼠标完成基线正式运行、瓶颈判断、修改缓存、再次正式运行、原完成按钮及返回实验室。没有注入完成记录或终端回应。

实际返回后选择「换个任务还会这样吗？」，查看对应回答与最终探索邀请，再回到终端、打开档案、打开旅程地图并返回。逐步检查：

- 壹回应的是本次实际完成的综合任务；此前关卡仍未完成。
- 就近存储面板位于工作区内；点击后容量实际变为四行，再次正式运行确实达到原目标。
- 两项回应和随时返回入口仍在；最终页的按钮回到终端，地图按钮进入真实地图。
- 阅读和选择回应不改变完成状态；再次返回不重复庆祝。
- 对应旧故事页仍显示“叙事候选 · 故事设定待确认”，档案阅读不授予关卡成果。

这些结果证明指定任务完成后的衔接，不证明全旅程通关、原生系统输入或真人理解。图形回放使用减少动效设置；打字中返回、回答中退出与取消退出的边界由既有 `test_narrative_review` 回归检查。
