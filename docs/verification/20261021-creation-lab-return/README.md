# 从作品回到实验室

离开创造工作台的现有确认框现在明确说明“保存草稿后离开”。如果当前可保存的输出尚未成为作品，会补充一句：想留下它，应返回编辑、命名后保存。原有取消、保存草稿、放弃修改的行为保持不变，没有新增弹窗或保存门槛。

## 真实保存与回应链路

新增 `test_creation_lab_return_input.gd` 从全新隔离的普通Game实验室开始，实际点击作品墙进入G3。学习、传输、整轮预测使用现有控制器准备，结果由真实模型产生；随后生成、离开确认、取消、保存草稿、命名保存、地图往返、终端和作品墙均通过Viewport输入。

两条路径分别验证：

- **只保存草稿就离开**：没有新增作品墙条目，不出现G3作品回应。重新打开后可用原配方再次生成同一输出，然后自行选择是否保存。
- **命名并保存作品后离开**：实验室从同一存档读取实际作品，壹使用真实G3支持记录作出回应；作品墙重新打开原输出和配方。再次回实验室不重复庆祝，往返及阅读没有改写作品文件。

壹的作品回应仍为已有短句，未经测试夹具直接注入。没有强制对话选择，继续探索和作品墙入口保持可用。本轮没有为测试再写新的庆祝台词。

这是指定创造路径的验证，不是从第一关完成60关的玩家旅程。场景仅取得实际完成的C/P/G记录，未通序章，所以终端仍按原导航推荐未完成的序章；截图中的进度不代表整部游戏已经完成。没有原生操作系统输入或真人理解验收结论。

## 画面与验证

[截图索引](gallery.html)包含中英文实验室、作品墙返回及离开确认框。主场景为1280×720；确认框单独保存其真实Window纹理，尺寸随语言布局确定。已目视检查中英文文案、可用操作与显示的作品。

相关测试为 `test_creation_lab_return_input`、`test_creation_route_flow`、`test_creation_navigation`、`test_lab_terminal_routing`、`test_lab_journey`、`test_creation_save_input`，另有导入和隔离存档检查。

结果：六项测试及两项环境检查全部通过。最终中英文图形回放各44项检查通过，共10张截图；502个运行与测试源文件和最终QA副本哈希一致，`git diff --check`通过。测试中的实验室回应、作品墙和G3完成均来自真实保存记录。

复现使用 `python -X utf8 scripts/verify-project.py --godot <Godot 4.7.1 executable>`，对上述套件分别指定 `--suite`。图形回放在已导入的隔离副本使用独立APPDATA及自定义user目录，参数为 `--windowed --resolution 1280x720 --rendering-method gl_compatibility --script res://tests/test_creation_lab_return_input.gd -- --locale=<zh_CN或en> --recovery-capture --evidence-dir=<证据目录>`。

运行命令、观察值与日志见 `logs/`，源码和截图校验值见 `evidence-manifest.json`。早期回放错误地向嵌入Window直接投递鼠标事件，取消按钮未收到点击；诊断后改为从根Viewport按窗口位置投递。失败日志保留在 `logs/exploration/`，没有通过修改游戏取消行为绕过问题。

## 保留边界与后续

模拟器、保存事务、存档结构、通关判定和作品上限未变。既有修改及三份来稿保留，没有提交、推送、合并远端或发布。弥拉、洪水、雕像、钥匙等故事候选继续待主创确认。
