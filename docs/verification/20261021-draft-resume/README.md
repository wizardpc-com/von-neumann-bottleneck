# 创造草稿恢复提示

重新打开带有已学模型的草稿时，底栏现在说明“草稿和已学规则已打开。按上方提示继续运行。”原先它总提示再次学习，与上方根据真实证据给出的下一步不一致。

新档仍引导选样例、学习；G3已保存作品仍显示作品回看提示；只读与异常存档仍优先显示原诊断。仅修改开场反馈，没有新增状态或持久化内容。

预测区的空状态改为“当前没有进行中的预测”，与历史完成证据区分。空轨道不再显示错误的 `1–0 / 0` 区间；已有格子的计数、分页和回放保持原样。

## 实际恢复路径

新增 `test_creation_draft_resume_input` 从隔离新档开始，通过现有下一步按钮实际学习、发送、预测和生成，在以下五个节点保存草稿并重新打开场景读取磁盘：

| 保存节点 | 重开后的实际下一步 |
| --- | --- |
| 已学习，尚未发送 | 发送并复原 |
| 已取得预测包复原证据 | 接未见输入 |
| 已提交一格预测但未揭晓 | 重新开始练习；未完成的一轮不计完成 |
| 整轮预测完成 | 接上回灌 |
| 已生成但尚未命名保存作品 | 用恢复的配方再次生成，再选择是否保存作品 |

每次重开均检查存档数据、已学模型及既有证据不变，且开场反馈不改写存档字节。最后的真实再生成与保存前的输出及配方完全一致，无需重复学习和预测。短公开原文和G3任务选择通过控制器准备，保存、下一步及其触发的学习／发送／预测／生成使用Viewport输入。

草稿不保存当前预测流和未保存为作品的临时输出，这是原有行为，本轮没有扩大保存范围。上方引导负责指出可做的下一步，底栏只说明已打开的内容，不把历史记录说成本次运行结果。

最终八项套件与两项环境检查全部通过，包含工作台原有385项检查；新增恢复路径无界面运行75项检查通过。图形检查使用实际学习／提交／揭晓产生的证据，没有注入完成记录。早期图形日志仍保留，最终运行身份以 `evidence-manifest.json` 为准。

最终中英文图形运行各79项检查通过，共8张1280×720截图。主控目视检查当前预测空状态、已完成标记、下一步操作与底栏，以及空轨道区间已隐藏、非空原文仍显示实际范围。504个运行与测试源文件和最终QA副本哈希一致。

复现：`python -X utf8 scripts/verify-project.py --godot <Godot 4.7.1 executable>`，逐项传入上述 `--suite`。图形运行在导入后的独立QA副本使用独立APPDATA和自定义user目录，参数为 `--windowed --resolution 1280x720 --rendering-method gl_compatibility --script res://tests/test_creation_draft_resume_input.gd -- --locale=<zh_CN或en> --recovery-capture --evidence-dir=<目录>`。
