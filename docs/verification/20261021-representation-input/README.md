# 表示章节：准备与服务的实际取舍

“准备一次，再服务”使用同一个分块方案完成两张独立订单：一次短读、八次完整扫描。每张订单各计一次准备，八次扫描的客户只在该订单内共用准备。原任务引导容易被理解为两张订单共用一次准备，现已明确这一区别，并补齐两张订单的时间和存储条件。

中文任务说明、请求预览、记录选择、结果表、结果标题与比较来源现在使用同一组订单名称。模型中的订单标识不变。原始表示与RLE按钮增加简短悬停说明，解释原始字节、连续重复计数和解码成本；没有给出分块地址或承诺压缩一定更省。

刘同学源稿06-4的“换回去”与本关实际主题不符，未采用其操作要求或结算断言。没有新增故事设定。

## 实际操作与结果

新增 `test_representation_player_input` 在独立Test模式进入本任务，随后只通过Viewport操作运行、修改编码、输入分割地址、选择块、复查旧记录和保存探索。未完成前置旅程，也未借测试入口授予成果。下面是验收用的真实运行结果，不出现在玩家提示中：

| 方案 | 每张订单的准备 | 短读总周期（上限105） | 八次扫描总周期（上限930） | 实际存储（上限80B） | 本次结果 |
|---|---:|---:|---:|---:|---|
| 整块RAW | 8 | 81 | 1096 | 68B | 八次扫描未达标 |
| 整块RLE | 89 | 111 | 769 | 72B | 短读未达标 |

每次均检查恢复出的真实字节、准备与服务之和、原完成判定。修改草稿后旧结果仍属于旧方案；复查RAW记录不会替换当前RLE草稿。最后只有本任务形成保留的达标方案，点击“保存探索”后存入原有独立档案。

混用方案只是本次验收的一种解法，没有新增固定分块要求。首屏用途、操作、完成条件减少重复说明，为两张订单的实际限制留出空间；详细机器成本仍在原滚动区域内。
