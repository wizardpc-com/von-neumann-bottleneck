## 设计决定（依据《美术风格约束 v0.1》§4–§5）

| 问题 | 之前 | 之后 |
|---|---|---|
| 窗口各章不统一 | 硬件、第一二章、第三四章各自覆盖窗口样式；第三四章用全局主题，顶边 2px 亮线 | `FloatingInstrumentPanel` 自带唯一窗体：石墨底、1px 细边框、柔和投影、10px 圆角；各场景不再覆盖 |
| 标题栏拥挤 | 38px 标题行 + 分隔线 + 22px 底部「◢」行；窗口按钮是带框的大按钮 | 36px 标题带（微亮底色、细分隔线），角色色标记 + 标题 + 自绘的「—／□／×」图标按钮（悬停才出现底色，关闭悬停变柔和红）；缩放手柄改为角落两道斜线，不占行 |
| 窗口层级不清 | 只有第一二章用边框表示焦点 | 所有章节：最后操作的窗口边缘带淡青色、投影更深、标题更亮；其余窗口退后 |
| 按钮墙 | 每个工具都是同样的带框按钮，和主操作抢视线 | 三级按钮：工具行无框（悬停浅底、打开时青色底线）；顶部导航为细描边；主操作（运行正式用例、运行全部订单／任务）保持实心 |
| 容器堆叠显"盒子套盒子" | 全局 `PanelContainer` 样式带投影和 2px 顶线 | 普通容器只是一层细线面板、无投影；投影只留给真正的窗口和对话框 |
| 窗口内小标题 | 紫色大字（「半加器用例」） | 标题字体、终端文字色、17px |

## 第二轮：引导光标与停靠布局（同日，按主创反馈）

- **引导带壹的光标**：引导条里的「当前一步」改为壹的逐字输出（操作引导以 2.2 倍于对话的速度写出），句末带光标；第二章按实际状态给出的「现在」也改为光标逐字。读过的句子再次出现时直接显示。
- **同一时刻只有一句在写**：步骤完成时先说短回应（已缩短为「跑起来了。」等），说完再写下一句引导。结算卡、设置等阻断层打开时，背后引导立即显示当前状态但不打字、不带光标；关闭后光标回到当前句末。
- **本关重心**：半加器开局的提示圈落在第一个还没有来源的目标输出端（按画面从上到下），不再指向元件按钮。
- **测试台**：搭建关卡进入时为左侧整高停靠栏，输入、实际结果和四组用例一屏可见；真值表说明移到用例下方、改为弱化小字。
- **元件台**：卡片高度 108→66，名称加一行用途，端口数移入悬停提示；放置说明移入搜索框提示；分组标题弱化；右侧停靠，高度跟随卡片数量（英文筛选行把宽度撑到 327px）。
- **布局稳定**：引导句放在固定两行高度的区域里，长提示不会改变引导条高度；「取消接线」只在拖线或放置元件时出现，并移到高度固定的导航行——此前它在英文工具栏里一出现就让工具栏换行、画布在拖线中缩放，英文真实输入回放因此失败，现已修复。进入关卡后玩家还没有操作时，窗口尺寸变化可以重新取景；一旦接线或运行，就不再移动画布。

验证（按主创要求减少测试次数，以针对性迭代为主）：受影响的 12 个套件一次通过 11 个，`test_ui_convergence` 的一条断言按“先回应、再引导”的新顺序更新后单独重跑通过（批次记录 `logs/round2-suites-results.json` 保留更新前的那次失败）。真实输入的 NOT → 半加器失败 → 改线 → 通过 → 封装回放中英文渲染均通过（`logs/round2-half-adder-input-*.txt`，截图 `screenshots/round2/`）。本轮未再跑完整回归。
