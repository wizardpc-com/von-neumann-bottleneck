## 采样范围与可比较条件

四个可玩工作负载均使用 17 条不可变记录，每条包含四个 4B 字段，复制空间上限
160B。温度工作负载包含八次字段 `[0]` 求和；混合工作负载包含八次字段 `[0,3]`
求和，以及一次读取索引 `[1,9]` 全部字段的稀疏查看。两者分别有同时到达
`batch` 和逐单到达 `serial` 条件。

网格对每个工作负载采样七种物理方案：不复制，以及将 `[0]`、`[0,3]` 或
`[1,2]` 各按记录排列、按字段排列完整复制一次并保留。查询记录块长度为
`1,2,4,8,17`，与复制字段和排列方式独立。请求分组范围如下：

| 工作负载 | 实验中可选 | 请求分组数 | 方案组合数 | 非支配指标类别数 |
| --- | --- | --- | ---: | ---: |
| `scan_batch` | 是 | 1、2、4、8 | 140 | 4 |
| `scan_serial` | 是 | 1 | 35 | 2 |
| `mixed_batch` | 是 | 1、2、4、8、9 | 175 | 5 |
| `mixed_serial` | 是 | 1 | 35 | 2 |
| `scan16_batch` | 否，额外探测 | 1、2、4、8、16 | 175 | 6 |
| `scan16_serial` | 否，额外探测 | 1 | 35 | 2 |

其中 385 组覆盖四个可玩工作负载，210 组来自额外的 16 次温度请求探测。
原始 JSON 用 `shipped:false` 标明后两组；它们不是另外两个可玩场景。
它们保留基础场景的 `task.id`，但完整任务内容参与条件身份，因此不会与八次请求
的结果混为同条件成绩。整个网格共有六个不同的完整条件身份。

“595 组组合”不等于 595 种不同的物理策略。例如，仅复制一个字段时，两种排列
可以得到相同访问行为；一些查询块和分组设置也会得到相同指标。表中的前沿先按
四维指标比较，再将相同指标向量归为一类。只有某方案四项均不差、且至少一项
严格更好，才支配另一个方案；没有加权总分。前沿只覆盖声明的采样集合。

## 实际可玩的取舍

Q1 表示公开请求顺序中第一个请求的真实响应周期，从本次模拟开始计时。
它不是最早完成的任意请求，也不是所有响应周期的最小值。分组执行时，后面的
稀疏查看可能先完成；这不会改变 Q1 的含义。

下表选择已交付工作负载中的前沿方案，查询记录块长度均为 1。所有周期和字节
直接来自上述 JSON，同一工作负载内才进行差值比较。

| 工作负载与方案 | 请求分组 | Q1 周期 | 总周期 | RAM 字节 | 峰值复制字节 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 同时到达温度：直接读取 | 1 | 307 | 2456 | 2176 | 0 |
| 同时到达温度：分组读取源数据 | 8 | 531 | 552 | 272 | 0 |
| 逐单到达温度：直接读取 | 1 | 307 | 2456 | 2176 | 0 |
| 逐单到达温度：保留温度字段复制 | 1 | 557 | 1362 | 980 | 80 |
| 逐单到达混合：直接读取 | 1 | 341 | 2784 | 2208 | 0 |
| 逐单到达混合：保留热点字段对复制，按记录排列 | 1 | 825 | 2404 | 1624 | 144 |

同时到达的八次温度请求允许按记录交替执行。源数据仍在缓存时完成其他请求的
相关计算，可以减少重新填充，所以总周期和 RAM 流量下降；Q1 必须等待这些
交替计算，响应更晚。这一取舍完全不需要物理复制。

逐单到达条件要求后一个请求在前一个完整响应后才能执行查询，因此分组固定为 1。
此时一次保留复制可以压紧后续反复访问的字段，以准备工作和空间换取后续复用。
不可变源数据允许提前用于复制，但其实际读取、写入和填充费用仍计入 Q1 等待。
没有为了平衡方案而附加调度罚时。

80B 和 144B 是复制分配的峰值，包含该分配的缓存行对齐；它们不是整个程序的
内存用量，不包含累加器和输出存储。此轮只支持一次完整保留复制，不支持滑动
复制窗口。上述同时到达温度和逐单到达温度的条件不同，不能将其指标混成一张
同条件排行榜。

## 成本核算与结果真实性

设 Q 为实际消费的查询值数，O 为实际输出值数，M 为实际复制的 4B 字数，
F 为实际缓存填充次数。本模型沿用现有内存操作成本：

```text
总周期 = 2Q + O + 10M + 16F
RAM 字节 = 4M + 16F
总周期 − RAM 字节 = 2Q + O + 6M
```

每个查询值包含一次 1 周期读取查询和一次 1 周期计算；每个复制字包含一次
1 周期源读取查询和一次 9 周期写穿；每次填充为 16 周期、16B；每个真实输出
为 1 周期。缓存为两行、每行 16B、全相联 LRU。连线、分组和分配释放没有
额外收费。最后一式是固定数值成本模型下的核验恒等式，不是周期与字节的一般
物理换算关系。

网格调用生产 `Model.evaluate()`，没有从旧探针、界面缓存或预设标量取得分数。
它逐方案检查公开顺序的完整输出、周期和流量核算、实际复制写事件、每个输出
仅收费一次，以及请求接纳和响应事件与指标的一致性。同时到达时所有接纳周期
为 0；逐单到达时下一请求的接纳周期等于前一请求的响应周期。最后响应等于总周期。

90 次重放来自 45 个选中组合：每个组合重新执行一次，再将任务和方案经 JSON
往返后执行一次，比较完整规范 Trace 的 SHA256。它不是对全部 595 组分别进行
90 次重放。每组结果同时记录完整条件、有效方案和 Trace 身份。

独立复核只读取归档 JSON，没有调用模型：重新计算全部六组的前沿、595 个有效
方案和完整条件 SHA256、Q1 和接纳响应关系、上述成本残差，以及采样排列的对齐
复制空间，均与证据一致。调用记录中的八项源码/网格 SHA256 也已与接受本证据
时的源码核对一致。

消费这份证据时应同时检查 `invocation.json` 的退出状态、日志和 JSON 的失败
列表，不能仅因 `frontier` 字段存在就认为运行成功。早期发现探针及其复制地址
起点错误留在上级 `discovery` 目录；本页的数值全部来自修正后生产模型的本次网格，
不将失败探针的前沿作为结论。

这份证据证明的是声明工作负载和有限方案集合中的真实策略取舍。它不证明所有
可能方案已被穷举，也不证明长期趣味性、新玩家体验、跨平台表现或最终界面验收。
