## 实际改动与兼容边界

Region原先为每位相同输入、独立冷缓存的客户端重复执行完整Base计算，
随后再次构造客户端专属证据。本轮只替换一处服务选择：在单次同步调用内
复用第一份已经完成的只读Base结果。生产修改限于
`experiments/representation_region/model.gd`的一行和两行说明。

每位客户端仍通过原路径生成完整的新事件，深复制事件详情和访问记录；
客户端标识、绝对周期、事件顺序、零时长请求、输出、缓存状态和费用都保持。
在线准备只做一次，十项服务计数仍逐客户端累加；`overfetch_values`和
`peak_cache_bytes`仍是原有单次服务含义。没有跨调用缓存、事件删减或共享
的可变客户端缓存。

Base先执行的错误优先级、第十一轮的一致拒绝结果、全部模型版本、条件身份、
正式订单、目标、存档和旧成果判定保持。保存方案和目标仍经实际公共模型
复算。保留GDScript，没有C++／Rust模块或新增依赖。
[契约审查](reviews/contract-review.md) · [实现复核](reviews/source-review.md)。
