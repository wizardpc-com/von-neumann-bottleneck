## 内部试玩方法

初次游玩可选 Game。从实验室点击终端或按 Enter，开始后按任务说明搭出第一条线路。熟悉操作后，可以自己决定是否继续追求更少的周期，或保留喜欢的作品。想集中测试不同章节、记录多次游玩体验时选 Test。两版各自保存，均可离线运行。

在 Test 里，遇到卡点或发现喜欢的玩法就按 F8，或点「现场反馈」。游戏会保留当时的截图、任务和方案，可以补一句“刚才想做什么，实际发生了什么”。输入会在本机自动保存。可以退出、下次继续。最后点「导出全部反馈」，将一个 ZIP 私下发给组织试玩的人。ZIP 可能包含作品、操作和自由文字。

## 维护者怎么收

用当前工作区的工具，把收到的 ZIP 导入私有目录。以下示例从仓库根目录运行，替换文件与目录路径。

```sh
python3 scripts/offline-playtests.py import /path/to/player.zip --library /private/path/playtest
python3 scripts/offline-playtests.py report --library /private/path/playtest --output /private/path/playtest/review.html
```

打开报告按任务、版本、类别查看现场。优先复核无法启动、存档丢失、无法继续及重复出现的操作卡点。可用新的最终 ZIP 补录前次会话，同一导出重复导入会去重。中断捕获的文件另外标出；打开原始 ZIP 可查看保留下来的内容。自动化合成回归使用自己的库，把真实玩家的反馈放在独立私有目录。

四包沿用离线设定。原有 Mac 联网 Test QA 包和 VPS 限源 8443 入口另行保留。本轮从当前 Mac 直连域名 GET /v1/health，系统证书校验通过，HTTP 200，API 1、schema 2、保留期 30 天。已有的实包同 ID 重发、SQLite 去重及删除证据见[受限公网验收](../20261122-feedback-connectivity/README.md)。其他玩家网络的准入及真实玩家批次需要单独验收；现有 QA 端点按单一 /32 放行，本轮无线上写入或部署。

## 工程验收

- 使用 Godot 4.7.1 stable 与匹配官方模板从 Git 归档导出。首次沙箱导入因无法创建隔离数据目录失败，保留了失败目录，以新批次重新导出成功。四包的逐文件哈希、ZIP 哈希、60 项任务清单、模板及两版独立存档路径通过 `scripts/check-edition-delivery.py`。两份 EXE 的架构为 x86-64，两份 Mac 可执行文件均含 arm64 和 x86_64。
- 两个真实 Mac 导出包使用隔离副本通过 `verify-mac-candidate.py`，验证了零预置通关、Game 正常解锁、Test 全部入口、自动保存重开、默认远程统计关闭和开发参数隔离。两份原始 App 的严格签名结构检查通过。
- 本轮工作区修复了教程测试台隐藏时的操作指引、维护者报告中断现场的可见性，以及 macOS 每日备份因 SQLite 临时共享内存文件报异常的问题。备份先在同文件系统的临时目录完成，再以独占硬链接发布关闭后的单文件快照。原有异常备份仍会触发告警。
- Python 检查覆盖品牌、打包、现场导入及报告；维护、接收器、社区、交付、私有报告和存储共 38 项通过。维护回归使用合成反馈实际执行删除、刷新报告、备份恢复与墓碑合并，VPS 仍运行先前版本。
- Apple M2 实际渲染的冻结 Test 包，在禁用出站网络并保护普通玩家目录的 QA 副本中，依次进入 60 项任务并核对当前任务身份。首次在教程、汇编、创造各记录一条，第二进程确认前次笔记与上下文保留，在服务工作台新增一条。仅导入最后导出的 ZIP 得到 2 次会话、4 条现场、4 张截图；重复导入去重，截图错误为零。归档的源码身份均匹配，探针结束后再次比对可执行文件与 PCK 哈希。详见[实包现场回执](mac-offline.json)。控制器驱动的入场与记录覆盖真实包的操作链，真人通关及长时间使用仍待试玩。
